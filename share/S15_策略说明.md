# S15 · Chandelier Exit + ZLSMA + BBW 策略说明

**这是一个趋势跟踪策略。** 不猜顶不猜底，只在趋势明确时进场，用固定风险控制仓位。

直接复制 `S15_CE_ZLSMA.pine` 的内容贴进 TradingView 的 Pine 编辑器就能跑。

---

## 一、三个部件怎么配合

| 组件 | 作用 | 回答什么 |
|---|---|---|
| **Chandelier Exit（吊灯止损）** | 判断多空趋势方向 | 方向变了吗？ |
| **Heikin Ashi + ZLSMA** | 判断 K 线有没有真的站上去 | 站对位置了吗？ |
| **BBW（布林带宽度分位）** | 判断当下波动率环境 | 现在适合做吗？ |

**为什么必须三个一起用**：

- 单用吊灯止损 → 趋势翻转后还会持续给同向信号
- 单用均线 → 震荡市会被反复打脸
- 不要 BBW → 震荡市里 CE 疯狂翻向（实测 1487 笔 −85.20R）

三个一起用，要求「方向变了」+「形态对了」+「环境适合」同时成立。

## 二、入场规则：三道闸门全部通过才开仓

### ① CE 方向翻转（事件，不是状态）

```pine
atr       = ta.atr(ceLen) * ceMult
longRaw   = ta.highest(high, ceLen) - atr
shortRaw  = ta.lowest(low, ceLen) + atr

// 棘轮：只朝有利方向移动，不回头
longStop  = close[1] > longStopPrev  ? math.max(longRaw,  longStopPrev)  : longRaw
shortStop = close[1] < shortStopPrev ? math.min(shortRaw, shortStopPrev) : shortRaw

// 状态机
dir = close > shortStopPrev ? 1 : close < longStopPrev ? -1 : dir[1]
```

**开仓触发是 `dir` 变化的那一刻，不是 `dir == 1` 的每根 K 线。**

> 早期实现是「只要 dir == 1 就出信号」，结果一根 K 线刷一次，信号数量是正确实现的 7 倍。
> TradingView 上的箭头是**翻转那一刻**画的。

### ② HA 关键 K 线

```
做多：HA 收盘 > ZLSMA 且 HA 收盘 > HA 开盘（阳线站上均线）
做空：HA 收盘 < ZLSMA 且 HA 收盘 < HA 开盘（阴线跌破均线）
```

**为什么用 HA**：指标输入是平均 K 线的收盘价，不是原始收盘价。用原始 K 线算出来的买卖点和图上箭头对不上。

### ③ BBW 分位 > 70%

```pine
bbBasis = ta.sma(close, 20)
bbw     = (2 * 2.0 * ta.stdev(close, 20)) / bbBasis * 100
bbwPct  = ta.percentrank(bbw, 100)      // 近 100 根（15m = 25 小时）的分位
```

**布林带宽度大 = 市场在动；宽度小 = 一潭死水，进去就是被磨。**

> **为什么不用 ADX / 效率比**：它们都滞后。等它们确认「趋势来了」，趋势已经走完，进场就是追高。
> 实测：ADX > 25 更差、ADX 上升 3 根 −5.54R、Kaufman ER > 0.25 −30.20R。

## 三、出场规则：四条并列，谁先满足谁全平

| # | 出场 | 条件 |
|---|---|---|
| ① | **止损** | 价格触及 20 根阶段低点（多）/ 最高点（空） |
| ② | **止盈** | 价格触及 入场价 ± 风险 × **1.2** |
| ③ | **趋势反转** | 收盘破 ZLSMA **且** 从**峰顶浮盈**回撤 ≥ **0.8R** **且** 连续 **2 根**确认 |
| ④ | **时间止损** | 持仓满 **16 小时** 仍未到 1.2R |

### 几个容易理解错的点

**止损为什么取 20 根阶段低点，不取关键 K 线的低点？**

取近的版本实测 3186 笔 **−632.52R**（被反复收割），取远才正期望。

**「回撤 0.8R」是从峰顶算，不是浮盈门槛。**

记录持仓期浮盈的最高点，从那个点掉下来 ≥ 0.8R 才平。不是「赚够 0.8R 就允许平」。
亏损单不会触发这条（因为没赚过），让止损说话。

**为什么时间止损是 16 小时而不是 4 小时？**

| 时限 | 笔数 | 净R |
|---|---|---|
| 4 小时 | 578 | +5.30R |
| 8 小时 | 563 | +11.55R |
| **16 小时** | 555 | **+21.71R** |
| 24 小时 | 551 | +17.73R |

平均持仓 6.93 小时、中位 4.50 小时。设 4 小时等于从中位数位置把一半单子砍断。

## 六、诚实说明：这套策略的弱点

### 1. 震荡市必亏

四段行情测试（每段 30 天）：

| 段 | 行情 | 净R |
|---|---|---|
| 第 1 段 | 单边涨 +12.1% | +10.38 |
| **第 2 段** | **震荡 −1.0%** | **−16.35** |
| 第 3 段 | 单边跌 −11.8% | +10.38 |
| 第 4 段 | 单边涨 +13.5% | +9.27 |

布林带宽度只能过滤「波动率低」的震荡，挡不住「波动大但来回甩」。

### 2. 成本极其敏感 —— 这是最致命的

同一套规则、2909 笔交易，只改手续费口径：

| 成本口径 | 净R |
|---|---|
| 市价 taker 0.05% + 滑点 | **−94.88R** |
| taker 无滑点 | −61.69R |
| VIP taker 0.04% | −71.65R |
| **maker 0.02%（挂单）** | **+8.02R** |
| maker 0.015% | +19.63R |
| 完全免费 | +54.49R |

**光费率口径就能把「赚」变成「亏」。**

策略每笔毛利约 0.019R，市价单成本 0.0525R/笔 = 毛利的 2.7 倍。
**所以这套策略必须挂单（maker）成交，市价单必亏。**

### 3. 参数是在同一批数据上选的

1.2R / 0.8R / 2 根 / 16 小时这四个参数，是在 120 天数据上选出来的。
邻域检查显示不是孤立尖峰（1.2R 那一行全部 +13.6~+17.9），但不等于未来有效。

### 4. 单币风险可能集中

曾出现单个币占全部利润 44% 的情况。

## 七、正确的预期

**这是一个「入场时机参考工具」，不是稳赚信号源。**

- 它能在趋势行情里抓到不错的波段
- 它在震荡行情里会亏
- 它的利润空间很薄，成本口径决定生死
- 它需要严格执行纪律，不能中途改参数

---

## 八、在 TradingView 上怎么用

1. 打开 TradingView，选一个永续合约（如 `BINANCE:BTCUSDT.P`）
2. 周期切到 **15 分钟**
3. 底部「Pine 编辑器」→ 全选删除 → 粘贴 `S15_CE_ZLSMA.pine` 全部内容
4. 点「添加到图表」
5. 策略参数可以在设置的「输入」标签里调

**注意**：
- TradingView 的成交假设（手续费/滑点/资金费）与本项目的 Python 回测不同，**两边数字不可直接比较**
- TradingView 用 `strategy.percent_of_equity` 按权益百分比下单，本项目用**固定风险法**（按止损距离反推仓位），所以仓位大小不同
- 这个脚本主要用来**验证形态判断**（信号箭头出在哪），不是验证收益
