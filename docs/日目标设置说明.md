# 日目标（落袋为安）设置说明

> 最后更新 2026-11-05。对应代码 `backend/daily_target.py`。

## 一、它是怎么运作的

一个四状态机，每 **10 秒**跑一次 tick（`engine.py` 里跟净值快照同一段）：

```
idle      未达标
  ↓ 浮盈 ≥ target_usd
armed     已达标，观察中
  ↓ 连续顶住 sustain_sec 秒
alerted   发飞书提醒，等你手动平
  ↓ 你平了 / 超过 auto_close_sec / 手动点「一键全平」
done      今天收工，不再开新仓
```

## 二、五个参数

| 参数 | 现在值 | 人话 |
|---|---|---|
| `enabled` | 开 | 总开关 |
| `target_usd` | **200** | 今天赚够 200U 算达标 |
| `sustain_sec` | **30** | 达标后要连续顶住 30 秒才算真达标 |
| `auto_close_sec` | **5** | 提醒发出后 5 秒强制全平（0 = 只提醒不砍） |
| `notify` | 开 | 发飞书 |

**这两个时间是一前一后串联，不是两个独立确认：**

```
达标 → 等 sustain_sec → 发提醒 → 再等 auto_close_sec → 强制全平
```

## 三、常见误解

### ❌ 「设 1 秒能更快提醒」

设 `1 / 1` 的真实含义：

```
达标 → 1 秒 → 提醒 → 1 秒 → 全平
```

**总共 2 秒就砍完了，你没机会反应。** 而且 tick 是 10 秒一次，
实际会在下一个 tick 一起走完。

### ❌ 「到了目标没反应 = 系统坏了」

`armed` 阶段要求连续满足 `sustain_sec` 秒。如果净值在目标线上下抖动，
每次掉到 `target × 0.8` 以下（200 → 160）会退回 idle 重新计时。

**建议值：**
- `sustain_sec` = 30~60（确认不是插针）
- `auto_close_sec` = **≥60，或 0**（0 = 只提醒不自动平，留给你自己判断）

### ❌ 「平完不能继续做」

`done` 状态会拦掉当天所有新开仓。要么等第二天 0 点，要么手动重置。

## 四、两个重置按钮

风控页「日目标」区底部：

| 按钮 | 行为 |
|---|---|
| **今日重置（今天不再自动触发）** | 清空状态 + **解除开仓封锁** + **当天不再自动触发日目标** |
| **重新启用今日目标** | 清空状态 + 允许再次触发 |

**日常用哪个**：

- 平完了还想继续做，但不想再被全平一次 → **今日重置**
- 点错了想恢复成正常状态 → **重新启用**

### 为什么需要两个（重要）

原来的 `reset()` 只清状态。如果净值还 ≥ 目标，**下一轮 tick 会立刻重新
armed → 再全平一次**。用户点了重置以为没用，实际是被平了两遍。

现在「今日重置」会记 `skip_day = 今天`，tick 开头直接 return，当天不再触发，
但 `blocked()` 返回 False —— **开仓不受影响**。

## 五、手动重置会不会影响风控

不会。日目标只管「今天赚够了要不要收手」，跟熔断线（`daily_loss_halt_pct`）、
并发、单边上限完全独立。重置日目标不碰任何风控数值。
