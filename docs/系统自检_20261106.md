## 二、🔴 影响交易正确性（2 项）

### 问题 1：55 个因子关闭 → 两道风控实际失效

**现状**：`factor_values` 里 56 个因子，只有 `mark_all` 是开启的（`enabled=True`），
其余 55 个全部 `enabled=False`，最后更新停在 **33.5 小时前**。

**受影响的是风控里这两道：**

| 风控 | 依赖因子 | 实际行为 |
|---|---|---|
| 事件静默 30 分钟 | `econ_cal`（财经日历） | 库里 50 个事件**全部是过去的**，未来事件 0 个 → `event_quiet()` 永远返回 `""` → **永不静默** |
| 恐惧贪婪缩仓 ×0.6 | `fear_greed` | 用的是 **33.5 小时前**的值（35.0）→ 即使真实值现在跌到 10（极度恐惧），也不会缩仓 |

**根因**：为了把流量从 20~30GB/天 压到 143MB/天，把 Clawby 采集关到只剩 `mark_all`
（`mark_all` 直接打币安，不耗 Clawby 额度，所以它是新鲜的）。

**影响评估**：
- **不影响 S15 的开平仓判断**（S15 只用 K 线，不用任何因子）
- **影响的是风控的保守动作**：本该在重要数据公布前 30 分钟停手的，没停；本该在极端情绪时缩仓 60% 的，没缩
- paper 模式下损失有限，**接实盘前必须解决**

**流量账**：这两个因子数据量极小 —
`fear_greed` 一天 1 次（几百字节）、`econ_cal` 一天几次（几 KB）。
**恢复它们一天增加不到 1MB**，相对于当前 138MB/天 可忽略。

**修复选项**：
- **A（建议）**：恢复 `fear_greed` + `econ_cal` 两个因子采集，其余 53 个保持关闭
- **B**：承认不要这两道风控，把 `event_quiet` / `size_multiplier` 代码删掉，配置里写明「不启用」
- **C**：保持现状（有旧值兜底，但不是真实数据 —— **最差的选择**，因为看起来在工作，实际是假数据）

### 问题 2：`rr_ratio: 1.2` 改了不影响交易

**代码链路（`backend/strategies.py`）：**

```python
rr = float(self._p("rr_ratio", 1.2))       # :681  读进来了
tp = px + risk * rr                         # :802  算出来了
...
if not (math.isfinite(stop) and math.isfinite(tp) and stop > 0 and tp > 0):
    continue                                # :815  tp 只参与这一个合法性校验
...
take_profit=0.0,                            # :830  传给引擎的是 0
```

**结论**：`rr_ratio` 只影响「tp 是不是正数」，**改 1.2 → 3.0 不会改变任何一笔交易**。

**为什么这样**：2026-11-06 把出场改成「2R 平一半、剩半放开跑」时，把 `take_profit` 硬改成 0
（否则引擎层的 tp 检查会在 1.2R 全平，永远走不到 2R 平一半）。

**修复选项**：
- **A**：`rr_ratio` 从 yaml 里删掉（和 `take_profit=0.0` 一致），代码里 `tp` 变量只用于合法性校验，注释说明
- **B**：保留参数但重命名成 `tp_sanity_mult`（说明它只做校验）

**建议 A** —— 一个不生效的参数比没有参数更危险。
