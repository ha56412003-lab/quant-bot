# 每日报告说明

> 建立日期：2026-11-05
> 每天早上 08:10 / 08:15 各发一份，飞书「嘿咻」+ 桌面端双通道

## 一、两份报告，各自解决什么问题

| | 空头验证日报 | 交易日报 + 复盘 |
|---|---|---|
| 时间 | 08:10 | 08:15 |
| job_id | `3a21cccfc50d` | `7063cdc0b4e4` |
| 模式 | **脚本直出**（no_agent） | **AI 分析**（agent） |
| 回答的问题 | 空头策略到底行不行？该不该关掉？ | 今天赚亏在哪？下一步怎么办？ |
| 特征 | 固定格式、纯数据、不烧 token | 有判断、有归因、有建议 |
| 脚本 | `scripts/short_report.py` | `scripts/daily_review_data.py` |

**为什么要拆成两份而不是合并**：

- 空头验证是**长期追踪**（7 天后下结论），数据口径必须天天一模一样，不能因为 AI 换了措辞就看不出变化 —— 所以用脚本直出
- 交易复盘是**每天不同的分析**，需要归因、需要判断，必须过 AI
- 混在一起的话，AI 的发挥会让长期趋势失去可比性

## 二、交易日报 + 复盘 的内容

### 数据采集（脚本负责，只出事实）

`scripts/daily_review_data.py` 采集 6 块：

1. **净值**：期初 → 最新，变化额和百分比，余额与浮盈亏拆分
2. **平仓交易**：每笔的时间、币种、方向、盈亏、平仓原因、持仓时长、策略
3. **开仓交易**：时间、币种、方向、价格、名义金额
4. **信号漏斗**：产生 → 真开仓 → 拦截，拦截率，Top5 拦截原因，多空分布
5. **当前持仓**：开仓价/现价/名义/浮盈亏/持仓时长/**止损距离**
6. **影子信号结算**：当日多空各几笔、胜率、期望 R
7. **异常检查**：单笔大额（>60U）、日志 warning/ERROR 数、净值跌幅接近熔断

### 复盘（AI 负责，出判断）

固定六段结构：

```
📈 交易日报 · <日期>
【今日成绩】净值变化 + 已实现盈亏 + 胜率
【今日操作】哪笔赚最多、哪笔亏最多、为什么
【今天的钱花在哪了】信号漏斗 + 最大拦截原因
【当前仓位风险】按止损距离排序，<2% 的必须点名
【复盘三问】最大的对 / 最大的错 / 重来会怎么做
【明日关注】2-3 条具体可执行的提醒
```

### 写进 prompt 的分析纪律

1. **先看数据再下结论** —— 亏钱不一定是策略错，可能是行情；赚钱不一定是对，可能是运气
2. **单日样本不作数** —— 1-3 笔交易得出的统计毫无意义，必须明说"样本太小"
3. **发现问题要说严重程度** —— 比如"止损距离只剩 1.28%，随时被扫"
4. **不重复罗列数据** —— 数据自己能看，要的是判断
5. **没交易就简短说明，不凑字数**

## 三、口径统一（重要）

**一天 = 本地 00:00 起**，不是 UTC 0 点。

原因：系统里 `db.day_start_equity()`（日初净值）、日内熔断 `daily_loss_halt_pct`、
日目标 `daily_target` 全部按本地 00:00 算。报告必须跟它们对齐，
否则会出现「报告说今天亏 2%、风控说已经亏 3.1%」的错位。

> 注：币安日线是 UTC 0 点切，但那是行情数据的概念，与账户记账无关。
> 别把两者混一起。
