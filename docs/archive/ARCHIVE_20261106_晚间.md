### 2. 监控池重排到 601px（`6235674`）

**问题**：表格下方出横向滑块。

**根因两条**：

| 根因 | 细节 |
|---|---|
| `scroll={{ x: 'max-content' }}` | 表格按内容撑开 → 800px vs 容器 602px，溢出 198px |
| 「杂讯过滤」列塞整句原因 | Tag 撑到 122px |

**改法**：删 `scroll.x`，改 `tableLayout="fixed"` + 固定列宽 —— 容器再窄只压缩内容，
不再出横滚条。

| 列 | 原宽 | 现宽 |
|---|---|---|
| 币种 | 90 | 80 |
| 现价 | 100 | 78 |
| 24h成交额 | 95 | 72 |
| ATR% | 80 | 58 |
| 插针比 | 85 | 56 |
| 池 | 62 | 50 |
| 杂讯过滤 | 92 | 62 |
| 最近信号 | 150 | 116 |
| **合计** | 754 | **601** |

**连带修的三处**：

- 表头 12px + padding 8px 在 72px 列里只放得下 56px 文字 → 「24h成交额」「杂讯过滤」折行
  → 单独给第一个 `.pnl` 的表头设 `10.5px / padding 6px 4px / nowrap / letter-spacing 0`
- 「杂讯过滤」原因整句移进 Tooltip，Tag 只留「通过/阻断」
- 「最近信号」3 行压 2 行 + 剥掉方向前缀（`空 · 空头方向已达上限` → `方向已达上限`）

**实测**：
```
8 列合计 601px / 容器 602px
.ant-table 602/602   .ant-table-header 602/602   .ant-table-body 587/587
anyHorizontalScroll = false    渲染 200 行
改前：800px / 602px，溢出 198px
```

**限制说明**：601px 是按 1920 宽窗口算的。窗口拖到 1366 会被压缩、个别文字折行，
**但不会再出横滚条**。

### 3. 信息流面板撑满高度（`68228c6`）

**问题**：面板底下空一大块。

**根因两条**：

1. **高度链断裂** —— `.pnl` 593px，内部 `.ant-card` 只有 213px，中间 7 层全是 `auto`，
   没有任何一层 `flex: 1` 往上撑。
2. **5 个表格全部写死 `scroll={{ y: 330 }}`** —— 容器 593px 只用了 330px。

**改法**：

- `v2.css` 加 `:has(.ant-tabs)` 高度链规则 —— 从 `.ant-card` 到 `.ant-tabs-tabpane`
  逐层 `flex: 1 + min-height: 0`。用 `:has()` 是因为页面里有 4 个 `.pnl`，
  只有信息流那个含 tabs。
- `ActivityTabs.jsx` 用 `ResizeObserver` 实测可用高度，把 `scroll={{ y: 330 }}`
  换成实测值（5 处）。

**过程中撞的四个坑**：

| 坑 | 现象 | 解法 |
|---|---|---|
| antd `scroll.y` 只是 `max-height` | 经济事件只有 3 条时表格缩回 75px，底部空 391px | CSS 补 `min-height` |
| 改 `el.style.minHeight` 被 React 重渲染冲掉 | 设了没效果 | 改下发 CSS 变量 `--act-scroll-y` |
| 高度不是行高整数倍 → 露半截行 | 信号流最底行被切一半 | 先按整行取整 → 仍剩 37–46px → 最终「行高平摊」 |
| `PARTIUSDT` 折行 | 该行高一截，取整逻辑全崩 | td 一律 `nowrap + ellipsis` |

**最终算法**（`finalRowH = floor(usable / nRows)`）：N 行正好铺满可用高度，
`--act-row-h` 下发到 td。ResizeObserver 加 4px 死区防 `setState → 重排 → 再触发` 抖动。

**实测**：
```
经济事件(3 条)   表格 75 → 442   gap 391 → 24
三道光闸(29)     442             gap 24
信号流(50)       462             gap 30   滚动 462/1363
成交记录(80)     462             gap 30   滚动 462/2100
运行日志(100)    462             gap 30   滚动 462/4422
```
剩余 24–30px 是容器内边距 + 边框，不是空白。

### 6. 持仓卡出场进度条重做（`4316301`）

**问题**：浩哥指出卡片上那条「距离出场的水平横线」失效了。

**根因 —— 不是视觉问题，是数学归零**：

```js
const tp = p.take_profit          // 改成 2R 平一半后 = 0
const wMax = long ? tp - entry : entry - tp   // 负数
if (wMax > 0 && lMax > 0) { prog = ... }      // 条件永远不成立
// → prog 恒为 0，条永远是空的
```

旧规则有「止盈价」这个终点；新规则 `take_profit = 0`，终点变成了 **2R** 和
**峰顶回撤**，这两个后端都不是现成字段。

#### 设计：一条条，三种含义

条的「终点」跟着持仓状态走：

| 状态 | 条的终点 | 方向 | 文字 |
|---|---|---|---|
| **Ⅰ 亏损中**（`curR < 0`） | 止损价 | 从右往左填绿 | `距止损 X.X%` |
| **Ⅱ 盈利未到 2R**（`0 ≤ curR < 2`） | 2R 价 | 从左往右填红 | `+X.XXR / 2.0R` |
| **Ⅲ 已到 2R / 已平半** | 峰顶 | 整条跑道 + 游标 | `½ +X.XXR 回撤 X.XX/0.80R` |

**Ⅰ 亏损**：条最左端画红色止损锚点（填到头就是止损）。逼近 0.7R 时整条呼吸脉冲。

**Ⅲ 跑道**：条代表「2R → 峰顶」这一段，红色渐变；青色竖条游标 = 当前价位置；
右端白色竖线 = 峰顶。进入跑道时闪一次，提示「已平半、开始放开跑」。
回撤逼近 0.6R 时呼吸脉冲警告。

**用的数据（全部来自现有 `/api/positions`，未改后端）**：

```
entry_price / stop_price / mark_price  → 1R 价格距离、当前 R
mfe_pct                                → 反推峰顶 R：peakR = mfe_pct/100 × entry / risk
half_closed                            → 判定是否已平半
```

#### 浩哥要求的两件事

**「行高不要太细」**：条 7px → **16px**；轨道背景 `.06` → `.09` 提亮
（原来在深色卡上几乎看不出轨道，这也是他觉得"细"的原因之一）。

**「加点动效」**（四处，克制）：

| 动效 | 触发 |
|---|---|
| 填充平滑推进 | 数值变化时 0.55s `cubic-bezier(.4,0,.2,1)` |
| 跑道游标滑动 | 价格走动时游标跟着滑 |
| 呼吸脉冲 | 亏损逼近止损 0.7R / 回撤逼近 0.6R |
| 一次性闪光 | 刚进入「已平半跑道」时 |

全部尊重 `prefers-reduced-motion`。

#### 行4 重排

状态数字（`11.5px / 900`，主位）+ 峰谷（`9.5px` 灰）+ 时间（`9.5px` 青）。

#### 踩坑（重要）

`.bar i` 在 `spider.css` 里写死 `width: 0`。想用 `inset: 0` 让跑道底色自动撑开，
但 **CSS 里 `width` 的优先级高于 `left/right` 自动撑开** → 跑道宽度塌成 0，肉眼完全看不到。
必须显式 `width: auto !important`。

**发现方式**：vision 说"看不出红色"，没信，直接量 `getComputedStyle` →
`trackRect.w = 0`。

#### 实测

```
CC  +0.40R → 填充 19.95%  （= 0.40 / 2  ✅）
LYN +0.66R → 填充 33.11%  （= 0.66 / 2  ✅）
条高 16px，卡片 130px，contentOverflow = false
8 张待进场空卡无变化，卡片高度统一
三态视觉：loss 止损锚点 ✅ / run 正向右填 ✅ / free 跑道游标 + 峰顶线 ✅
```

**尚未看到实景**：截至归档时两笔持仓都在 2R 之前，`loss` 和 `free` 两个状态
是用临时改 DOM 造出来验证的（刷新即恢复，没动数据库）。
等真有一笔跑到 2R 自动平半，才能看到真实效果。

## 三、本轮踩坑汇总（可复用）

| # | 坑 | 教训 |
|---|---|---|
| 1 | `scroll.x: 'max-content'` 让表格按内容撑开 | 要固定列宽用 `tableLayout="fixed"`，删掉 `scroll.x` |
| 2 | 表头字号/内边距在窄列里放不下 | 字号和 padding 要按最窄列反算 |
| 3 | 高度链中间断了一层，`flex` 传不下去 | 用 `:has()` 精确选中目标容器；中间每一层都要 `min-height: 0` |
| 4 | antd `scroll.y` 只是 `max-height` | 数据少时表格会缩回内容高度，必须补 `min-height` |
| 5 | 直接改 `el.style.minHeight` 被 React 重渲染冲掉 | 改下发 CSS 变量 |
| 6 | 高度不是行高整数倍 → 露半截行 | 行高平摊 `floor(usable / nRows)` |
| 7 | 单元格长文本折行打乱取整 | td 一律 `nowrap + ellipsis` |
| 8 | 多插一层 div 后 CSS `> ` 选择器失效 | 检查选择器层级 |
| 9 | 改 `overflow: hidden` 容器时漏搬圆角 | 圆角要跟着容器一起搬 |
| 10 | `.bar i` 的 `width: 0` 压过 `inset: 0` 自动撑开 | 绝对定位要撑满时显式写 `width: auto` |
| 11 | 不同配置的回测数字混在一起讲 | 分开标注口径，否则校验会误判 |
| 12 | vision 目测"偏细/偏长/背景粉色" | **不可全信**，用 `getComputedStyle` / 像素采样复核 |
