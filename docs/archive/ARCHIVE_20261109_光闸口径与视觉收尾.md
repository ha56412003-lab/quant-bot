## 二、「四道光闸」面板口径演进（核心）

### 2.1 这张表到底在回答什么

**只回答一个问题：这个币现在能不能开仓。**

它不回答「我手上有什么」，也不回答「这个币好不好」。
所有让人产生第二种理解的写法，都是 bug。

### 2.2 演进过程

**第一版（错误）**：策略层直接把 `verdict` 写成「已开仓」。
问题：`strategies.evaluate()` 里的「已开仓」只是说「这个币已经持仓，跳过判断」，
被 `risk.allow_entry` 拦下的单子（比如已达日目标、熔断）也会写成「已开仓」，
于是出现 **RSR 显示已开仓、实际根本没开** 的假象。

**第二版（`aea3e31`）**：策略层只写「四闸全过」，由 `/api/gates` 用**真实事实**覆盖：

```
持仓表里真有这个币              → 「已开仓」、opened=True → 绿标签
四闸过 + 本根新鲜信号被拒        → verdict = signals.skip_reason → 橙字
四闸过但无新鲜被拒记录           → 「四闸全过·待成交」→ 灰
四闸没过                        → _GATE_STATE[sym]["why"] → 灰
```

**第三版（`7b4c229`）**：加两道收紧 ——

1. 必须先 `v["ok"]` 为真才允许显示 `skip_reason`（不然四闸没过的币也会挂拒绝原因）
2. 信号必须**新鲜**：`sig_ts >= v.ts` 且 `now - sig_ts <= 300` 秒
   （起因：点了「今日重置」后，早上 06:45 的旧拒绝原因还挂在页面上）

**第四版（`ad803f8`）**：池外的币说清原因。
池外的币**永远不被扫描**，`_GATE_STATE` 里留着的是几小时前的旧判定，
于是页面一直挂着「四闸全过·待成交」，看起来像在排队等成交。
实测那 5 个币全部 `in_monitor=False`、EFF 全部低于 0.30：

```
LINK 0.297（差 0.003）  XLM 0.275  NEAR 0.255  ONDO 0.194  TAO 0.153
```

改为三条文案：

```
eff 为空            → 「池外·不参与扫描」
eff < EFF_MIN(0.30) → 「池外·EFF 0.15 未达 0.30」
否则                → 「池外·池满未入选」
```

排序同时改成「池内优先」：在池 > CE > HA > 偏离 > BBW。

### 2.3 持仓币该不该出现在这张表里（来回两次）

**`095632e`（加回来）**：
`strategies.evaluate()` 对持仓币直接 `continue`（不需要再判断能不能开），
所以不写 `_GATE_STATE`，`/api/gates` 遍历时就没有它 → **板上消失，像已经平了**。
这就是「STRK 没有平啊 还在跑」那次误判的根因。
当时的修法：`/api/gates` 把持仓币补进列表，四闸字段留空，结论固定「已开仓」。

**`ee9faf2`（又撤掉）**：
浩哥驳回，理由不在代码：

> 「还是恢复之前那样，4 道光闸里不显示已经持仓的吧。感觉显示了视觉上信号乱了
> （如 LIT 这个，已经开仓了，光闸里还一直显示 CE 反转打勾，不知道这个是又出现
> 反转了，还是啥）」

**这是真问题**：持仓币的 `ce/ha` 是**开仓前那一刻**留下的旧值，之后不再更新。
挂在表上一行「CE ✓」，读的人无法判断这是「刚刚又反转了一次」还是「三小时前的老账」。
**信息正确 ≠ 信息可用。**

**现在的分工（写死，别再混）：**

| 想知道什么 | 去哪看 |
|---|---|
| 这个币现在能不能开仓 | 四道光闸（只列未持仓的币） |
| 我手上有什么仓、赚亏多少 | 持仓卡 + 持仓明细表 |

**`469dc93`（顺带）**：持仓的币不再挂「池外」标签 ——
池内池外只决定「能不能开新仓」，对已经开了的仓位毫无意义，
和「已开仓」并列时看起来像「没人管」。
（实际上出场完全不走池子：`engine.position_loop` 遍历 `db.open_positions()`，
`strategies.check_exit` 内没有任何 monitor 判断，池外仓位照样受全条出场规则保护。）

### 2.4 保留的一条硬规则

**前端 `null` 必须显示 `-`，绝不画 ✗。**

老代码 `render: (v) => v ? ✓ : ✗` 把 `null`（这轮没扫过）画成 ✗（这道闸没过），
误导极强。`dir / ce / ha` 三个字段全部改掉。

## 三、两处视觉（`819e1cf`）

### 3.1 持仓操作区去掉滑块

**表面问题**：持仓满 6 个时冒出一条纵向滚动条。

**第一反应改错了地方**：改 `Dashboard.jsx` 的内联样式 `height:420, overflow:'auto'`
→ build 完浏览器仍是 420px。**因为真正的凶手在 CSS 里**：

```css
/* v2.css */
.spider-root .stage > div:nth-child(3) {
  flex: 0 0 420px !important;
  height: 420px !important;
  min-height: 420px !important;
  max-height: 420px !important;
}
```

`!important` 压过内联样式，改 JSX 白改。

**算清楚为什么满 6 个才冒出来**：

```
持仓行实际 49px（多了补保输入框 + 三个平仓按钮）
空行 36px，表头 34px，表格固定补足 10 行

6 个持仓：6×49 + 4×36 + 34 = 472px  >  420  →  溢出 → 出滑块
3 个持仓：3×49 + 7×36 + 34 = 433px  >  420  →  也溢出，但不明显
```

**修法**：容器不再锁高（`flex:0 0 auto` / `height:auto` / `overflow:visible`），
行高统一压到 36px。表格本来就固定 10 行，所以 `10×36+34 = 394px` 恒定。

**实测三种情况（浏览器注入假行模拟，纯净刷新后恢复）：**

| 仓位 | 表格高 | 滑块 |
|---|---|---|
| 3 仓 | 400px | 无 ✓ |
| 6 仓（模拟） | 414px | 无 ✓ |
| 8 仓（模拟） | 424px | 无 ✓ |

## 四、测试取样起点重置（本次）

### 4.1 为什么重置

从 11-05 到 11-09，参数改了不止四轮：
池子 ATR 进池线、风控三参数（1.5% / 8 并发 / 6x / 32%）、
进场偏离闸 0.5%、出场快速失败 4h·0.5R、监控池口径换成 EFF。
**跨版本混着算胜率，等于把旧规则的成绩算到新规则头上。**

### 4.2 重置到什么

```
起点：2026-11-09 12:00
结束：2026-11-16 12:00（满 7 天）
基线净值：自动取起点后第一条 equity_curve（不手填）
```

### 4.3 怎么实现的（一处改，两处生效）

`backend/config.py` 新增唯一常量：

```python
SAMPLE_START_STR = os.environ.get("QB_SAMPLE_START", "2026-11-09 12:00")
SAMPLE_START = _parse_sample_start(SAMPLE_START_STR)      # datetime | None
SAMPLE_START_TS = SAMPLE_START.timestamp() if SAMPLE_START else None
```

消费方两处：

- `backend/db.py::shadow_stats()` —— 加 `AND ts >= SAMPLE_START_TS`
  （以前**完全没有时间过滤**，统计的是全部历史）
- `scripts/observe_report.py` —— `START = config.SAMPLE_START`，
  `BASE_EQUITY = None` → 自动取起点第一条净值

**以前两处各写一个日期，所以每次改都要改两遍，必然漂。**

### 4.4 生效时点

12:00 之前跑报告会显示「基线 0.00 U（无数据）」「已过 -1.2 小时」，
这是正常的 —— 起点在未来。12:00 后第一次 `tick()` 写入净值点，基线自动填上。
