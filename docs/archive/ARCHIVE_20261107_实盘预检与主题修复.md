## 二、背景：为什么要在切盘时做自检

### 2.1 逐仓是生死线

浩哥原话：

> **「现在 OKX 和 Bitget 用的都是全仓 cross，接实盘必须改成逐仓 isolated，否则一个币爆仓会带崩整个账户。作为配置实盘的第一个重要提醒」**

全仓 6 仓 × 6 倍，只要一个币走极端，整个账户归零。这是一票否决项，不是优化项。

### 2.2 「币安设不了逐仓」是假象

浩哥 App 里手动切逐仓，弹窗：

> **「联保模式下不支持切换逐仓」**

查币安官方 FAQ，原文：

> **「请注意，多资产模式仅支援全仓模式。您可以在单资产模式与多资产模式之间轻松切换，而无须关闭现有仓位。」**

**根因坐实**：联保（多资产模式）与逐仓天生互斥，不是币安不支持逐仓。

App 路径：`【合约】-【U 本位合约】→ 右上角【单】/【联】→【单币保证金模式】`，**不用平仓**。

### 2.3 逐仓是「按币种」设的，不是全局

币安与 OKX / Bitget 的根本差异：

- **OKX / Bitget**：保证金模式写在下单参数里（`tdMode` / `marginMode`）
- **币安**：`POST /fapi/v1/marginType` **按币种单独设**，官方「切换保证金模式仅适用所选合约」

所以浩哥当时的质疑——**「一天跑200个B，我要预先把这200个B在APP里先一个个设置成逐仓？」**——顾虑成立，但不用这么办：

**只对要开仓的 symbol 设，最多 6 并发、约 9 次开仓/天；设一次记住，重复设返回 `-4046` 忽略。**

## 三、四件事的最终形态

### ① 开仓强制逐仓（`fc8f14e`）

```
binance.set_margin_type(symbol, "ISOLATED")
  → POST /fapi/v1/marginType {"symbol":"BTCUSDT","marginType":"ISOLATED"}
  → "changed" | "already"(-4046)

executor 开仓顺序：
  算仓位 → 【设逐仓】→ 设杠杆 → 下单 → margin_of 事后核对
  设不了 → db.log error + return None（放弃开仓）
```

**宁可错过一次机会，也不在全仓里悄悄开出去。**

错误码：`-4046` 已是该模式（当成功）/ `-4047` 有挂单不能改 / `-4061` 持仓方向不匹配。

### ② 关闭联保：代码只检查，不自动关

`multi_assets_mode()` 必须是 `False`，不通过就拦。

**为什么不自动关**（三条理由，浩哥接受）：

1. 账户级开关，系统私自改用户账户设置
2. 关掉后 BTC/ETH 不能再当保证金，可能让既有仓位保证金不足甚至强平
3. 一次性设置，写自动逻辑等于埋隐患

`live_precheck.py --fix` 保留显式人工通道（默认只查不改）。

**能关**：`POST /fapi/v1/multiAssetsMargin` `{"multiAssetsMargin":"false"}`，官方「on Every symbol」，一次全账户生效。

### ③ 双向交易不改、代码自适应

**没有打开双向交易**，理由：S15 对同一个币永远只有一个方向（`max_same_side` 限着），开双向没好处；双向模式下每笔必带 `positionSide`，漏一个就 `-4061` 全军覆没。

```
executor._is_hedge()   查 GET /fapi/v1/positionSide/dual，缓存 300s
                       查不到按单向（与改动前一致，不会更差）
executor._pside()      双向 → LONG/SHORT；单向 → None
开仓、平仓两处都传；hedge 下不传 reduceOnly（币安不接受）
```

### ④ 切盘自检 + 弹窗拦截

```
GET  /api/live/precheck
  → {"ok":bool, "items":[{key, ok, label, detail, fix, required}]}
  items: apikey(required) / multi(required) / hedge(required=false 只记录)
  没 key 直接 ok=false —— 不拿「查不到」冒充「没问题」

POST /api/mode {"mode":"live"}
  → 先跑预检，required 项不过 → HTTP 400 + detail 数组，mode 不变
  （防绕过界面直接调接口）

前端点「切换实盘」
  → 先请求 precheck → 弹窗
  → 有问题：标题「还不能切实盘」，逐条 ✓/✕ + 修复路径，只有「知道了」
  → 全过：才出现输入框，confirmText !== 'LIVE' 时「确认切换」保持 disabled
```

## 四、三个真坑

### 坑 1 · 预检弹窗的遮罩

浩哥：**「你说的这两个问题都不用改，但是弹窗还是设置成只弹窗，背景页面不要遮罩」**

`mask={false}` 去掉黑罩后，发现**背景看得见却点不动**——`.ant-modal-wrap` 仍是全屏 fixed 且吃点击。

补：

```css
.lc-wrap { pointer-events: none; }
.lc-wrap .ant-modal { pointer-events: auto; }
```

**实测**：遮罩不存在 / 背景 (80,120) 取到的是页面元素 / 弹窗开着点背景导航真的能切页 / 6 个取样点像素差全为 0。

### 坑 2 · 总览页导航「黑底黑字，自己盖自己」

浩哥：**「玫红主题下这个总览页，总览的按钮是黑色的，然后切换主题的按钮也是黑色的，改成跟配置他们一样的样式」**

查出来比看到的更严重：

```js
// SpiderBoard.jsx 选中态 inline style
background: 'rgba(27,6,19,.85)',   // 近黑
color:      '#1b0613',             // 同一个黑
```

**字和底一个颜色，字自己是看不见自己的。**

未选态是 `2px` 粗黑框 + `11px` / `font-weight 800` 等宽体，压粉色标题轨上整排发沉。

改法：
- JSX 去掉 inline style，改 `className='btn on'` + `aria-pressed`
- CSS 对齐配置页：`1px` 细边 / `3px` 圆角 / `12px` / `weight 400` / `padding 5px 12px`
- **必须带 `!important`** —— `v2.css:778` 那套 `.spider-root .hdr .btn` 从头到尾 `!important`，不加压不动
- 只作用 `html:not([data-theme])`（玫红）；MAC 两套已是极简无边框、纸面是浅底，各不动

**一次性发现**：选中态原想用白字，实测只有 **4.03:1**（粉底上白字最多到 4.19），过不了 AA → 改深字 **4.53:1**，靠底色块区分选中。

### 坑 3 · antd token 传 CSS 变量 → 全局 danger 隐形 ★

浩哥：**「玫红主题 配置页「切换实盘」按钮也存在同样问题，黑色字 黑色按钮，融到黑色背景里看不到了」**

根因不在样式，在 token：

```js
// main.jsx:18-19
colorSuccess: 'var(--green, #3fa86a)',
colorError:   'var(--red, #d4595e)',
```

**antd 的 token 不认 CSS 变量** —— 它要用具体色值跑 `@ant-design/colors` 派生 hover / active / border。传 `var(...)` 解析失败，整条色阶退化成 `#030303` 近黑：

```
切换实盘  bg rgba(0,0,0,0) / color rgb(3,3,3) / border rgb(3,3,3)
压 colorBgContainer #0b0c12 → 完全隐形
```

**影响面不止这一个按钮**：所有 danger / success 类组件（含表单报错）都受害。

修两层：
1. token 改实色 `#3fa86a` / `#d4595e`（另外三套主题本来就是实色，所以这 bug 只在玫红存在）
2. 改完 `darkAlgorithm` 仍把它压成 `rgb(183,79,83)`，实测 **4.07:1** 不够 AA → `spider.css` 提到 `#ff6b6b`，**7.10:1**

限定 `:not(.ant-btn-primary)`，不动实心 danger 的底色。

> **教训**：antd ConfigProvider 的 token 一律写静态色值；要跟 CSS 变量联动只能在组件层用 CSS 覆盖，不能在 token 里塞 `var()`。
