# 归档 · 2026-11-06 深夜 —— S15 出场规则两次改造（K5 + 半仓止盈）

> 本文件记录 2026-11-06 22:00 ~ 23:40 对 S15 出场体系的两轮改造。
> 起因：浩哥发现「LYN 回撤 0.8 出局都是负盈利」—— 固定 0.8R 回撤线在峰顶不足
> 0.8R 时，出场价落在负 R 区，等于赚过的钱全吐光还倒亏。
>
> 两轮改造后 S15 出场从「四条规则」变成「五条规则」，其中第③条本身又分两段。

## 一、起因：一个被忽略三年的结构性缺陷

### 现象
2026-11-06 晚，持仓 LYNUSDT（做空）峰顶浮盈 **0.73R**，随后一路回撤。
按老规则「连续 2 根破 ZLSMA50 + 从峰顶回撤 ≥ 0.8R」，出场点必须是
`0.73 − 0.80 = −0.07R` —— **浮盈全部吐光，还要倒亏 0.07R**。

### 定性（`trail_check.py` 分桶实证）
954 笔回测样本里，被「均线破+回撤」带走的仓位按峰顶分桶：

| 峰顶区间 | 笔数 | 其中均线破回撤 | 小计 R | 均值 R |
|---|---|---|---|---|
| 0.0~0.3R | 247 | 112 | **−86.19** | −0.77 |
| 0.3~0.5R | 116 | 78 | **−47.82** | −0.61 |
| 0.5~0.8R | 140 | 92 | **−30.75** | −0.33 |
| 0.8~1.2R | 135 | 101 | −8.93 | −0.09 |
| 1.2~2.0R | 164 | 120 | +59.72 | +0.50 |
| 2.0R+ | 152 | 152 | **+299.86** | +1.97 |

**峰顶不足 0.8R 的那 282 笔，全部亏损，合计 −164.76R，0 笔盈利，均值 −0.58R。**

这就是固定回撤线的病根：**它保证你能留住 0.8R，但前提是你先赚到 2R 以上；
赚不到 0.8R 的仓位，它就是一条「必须亏着走」的线。**

## 二、第一轮改造：第③条改为分段（K5）

### 方案
```
峰顶 < 2R：连续 5 根收盘破 ZLSMA50 + 从峰顶回撤「峰顶浮盈 × 50%」（上限 0.8R）→ 全平
峰顶 ≥ 2R：完全不变（2 根 + 固定 0.8R）
```

效果：峰顶 0.6R → 回撤 0.30R → **在 +0.30R 走，永远留住一半**。

### 8 组参数扫描（60 天 / 20 币 / 954~975 笔）

|---|---|---|---|---|---|

| A 3根+50% | +50.25 | −11.74 | 45.2% | −42.4 | 1.19 |
| F4 4根+50% | +55.25 | −6.75 | 46.2% | −44.3 | 1.247 |
| G5 5根+50% | +63.38 | +1.39 | 46.4% | −48.6 | 1.304 |
| H6 6根+50% | +56.58 | −5.42 | 46.9% | −50.9 | 1.111 |
| I 4根+55% | +57.48 | −4.51 | 46.0% | −44.7 | 1.17 |
| J 4根+50% 限0.8R | +58.60 | −3.40 | 46.3% | −44.3 | 1.18 |

**加 0.05 护栏后重跑：K5 = +67.61R / 47.0% / DD −49.2 / 比 1.375。**

### 为什么是 5 根
3 根太敏感，被假突破提前打掉（+50.25R，比现行少 11.74R）；
4 根 +55.25R；**5 根 +63.38R（峰值）**；6 根回落到 +56.58R。

### 为什么必须加 cap 0.8R
不加 cap 时，峰顶 1.8R → 50% = 0.9R，**比原来的固定 0.8R 更宽松**，
反而拖后出场，与「≥2R 段」的衔接出现跳变。加上限后峰顶 ≥1.6R 一律按
0.8R 算，两段平滑过渡。

### 为什么必须把峰顶落库
K5 的门槛 = `峰顶 × 50%`，而 `peak_r_mem` 原来只活在内存
（`_S15_POS_STATE`），**进程一重启就归零**。归零的后果不是"门槛变严"，
而是**门槛算成 0 → 任何回撤都触发出场**。实测 LYN 出现过
`trail_target_r = 0.00`，属于会乱砍仓的危险状态。

修法：
- `db.py` 加 `peak_r` 列 + 加入 `_POSITION_WRITABLE`
- `strategies.py` 峰顶更新时**节流落库**（每抬高 0.05R 才写一次）
- 三重兜底初始化：`peak = max(库里的 peak_r, 由 mfe_pct 反推的值, max(0, 当前R))`
  —— 以后重启不再依赖手工回填
- 三处同款护栏 `use_pct = trail_pct > 0 and 0.05 < peak < trail_pct_max_r`
  （实盘 / API / 回测保持一致），峰顶太小时退回固定 `trail_r`

### 被数据否掉的三个安慰性方案

**① 统一调小 `trail_r`（解决倒亏的直觉方案）**

|---|---|
| 0.3 | +14.64 |
| 0.5 | +15.29 |

调小确实压住了 282 笔小亏，但峰顶 2R+ 的 152 笔（+299.86R）会被浅回撤扫走。
**必须分段，不能一刀切** —— 这正是 K5 的动机。

**② 加保本止损（浮盈到某值后把止损上移到成本价）**

**③ 回撤超标就不等穿线根数（强行平仓）**

**全崩。** 那些「看着已经亏很多」的瞬间，往往正是回调的尾巴，

## 三、第二轮改造：半仓出场加「再满 2R 止盈」

### 浩哥的要求（原话）
> 「第②场方式 浮盈 ≥ 2.0R 平一半，然后剩下的一半（半仓基数的浮盈回撤50%）
> 或半仓基数顶峰回撤0.8R 或半仓基数又盈利满2R 3个条件并列 达到其中一个就出场」

后续澄清：
> 「第②条出场……平完之后剩下的半仓归第③条管 **这个不变** 加一条再满2直接出场」

### 追加实验：半仓到底该不该「另开一本账」（`half_fresh`）

**浩哥的疑问**：「我要的是剩下的半仓跑出场③的时候，按照全新的票来跑，
不继承已经平掉的数据」。

这是两种完全不同的口径，都实现了、都回测了：

| 口径 | 半仓的峰顶 | 半仓的破线计数 |
|---|---|---|
| **继承（现行）** | 全程高水位（含平半前那段） | 从开仓起连续累计 |
| 全新票 | 从平半那一刻重新爬 | 从平半那一刻重新数 |

**实测差别（平半在 2.0R，之后半仓涨到 2.5R）**：
```
继承口径：峰顶 2.5R → 走段B → 门槛固定 0.8R → 跌到 1.70R 才走
全新票：  峰顶 0.5R → 走段A → 门槛 0.5×50%=0.25R → 跌到 2.25R 就走
                                          ↑ 早走 0.55R
```

**回测（60 天 / 20 币）：**

| 方案 | 笔数 | 净总R | 对 K5 | 胜率 | 回撤R |
|---|---|---|---|---|---|
| K5（半仓继承全程） | 963 | +67.61 | — | 47.0% | −49.2 |
| **K5 + 再满2R【现行定稿】** | **965** | **+70.77** | **+3.16** | **47.0%** | **−48.1** |
| K5 + 再满2R + 全新票 | 954 | +63.10 | −4.51 | 46.9% | −50.3 |
| K5 + 全新票（不加止盈） | 950 | +61.35 | −6.26 | 47.1% | −49.7 |
| K5 + 全新票 + 三条件 | 982 | +59.71 | −7.90 | 46.8% | −50.2 |
| K5 + 全新票 + 回撤0.8R | 975 | +58.95 | −8.66 | 47.1% | −50.4 |

**结论：全新票口径少赚 7.67R，且回撤更大（−50.3 vs −48.1）。**

**为什么「逻辑更干净」的方案反而更差**：全新票让半仓回到段A
（5 根 + 回撤 50%），而半仓刚起算时峰顶只有零点几 R，比例门槛只有
零点几 R —— 一点回调就被扫出。等于给「让利润奔跑」的那一半套上了
小仓位的紧箍咒。

**回撤反而更大**：把本可以跑成大赢家的仓位提前砍成小赚，剩下的仓位
质量变差，净值曲线更抖。

**决策（浩哥 2026-11-06 拍板）**：「那就不变吧」——
保持继承口径，`half_fresh` 只作为回测参数保留，实盘不启用。

### 追加修复：0.05 护栏不该决定穿线根数（浩哥发现）

**现象**：新开仓的 BLESS 卡片上显示「破均线 0/2」，按规则它峰顶才 0.04R，
显然不足 2R，应该走 **5 根**。

**根因**：`use_pct = trail_pct > 0 and 0.05 < peak < trail_pct_max_r`
这一个判断被两个用途共用 —— 既决定门槛算法，又决定穿线根数。
`0.05` 护栏本来只是为了防止「峰顶接近 0 时比例门槛算成 0 → 任何回撤都出场」，
但它连带把根数也切成了 2 根。

**修法**：拆成两个判断。
```
in_lt    = peak < trail_pct_max_r        # 根数：不足 2R 一律 5 根
use_pct  = 0.05 < peak < trail_pct_max_r # 门槛：峰顶太小退回固定 trail_r
```

**坑中坑**：`main.py` 的 `else` 分支里还留着一行 `ma_bars_need = ma_confirm`，
把前面算好的值又覆盖了回去 —— 第一次改完 API 仍返回 2，靠实测才发现。

**复检方式（三层，缺一不可）**：
1. `check_k5.py` 公式复算 —— 9 个峰顶点 × 门槛/根数/比例标志，全部对上 API
2. `test_half_path.py` 真实调用 —— 18 项断言，覆盖段A根数、段B根数、半仓继承、
   半仓止盈边界（3.9/4.0/4.1R）、两条件同时满足的优先级
3. 浏览器实测 —— 三张卡「破均线 N/M」文案 + 小点个数 + 出局三角颜色

**复检中发现的一个「测试写错、代码是对」的例子**：我一度断言「峰顶 0.04R、
cnt=5 就该出场」，实测不出场 —— 因为它回撤才 0.02R，而门槛是固定 0.8R。
**代码是对的，我的测试错了。** 刚开的票本来就不靠第③条出场，靠硬止损兜底。

**代价（必须记住）**：

| 口径 | 净总R | 胜率 | 回撤R |
|---|---|---|---|
| 旧：护栏连带切根数 | +70.77 | 47.0% | −48.1 |
| **新：根数只看 2R 分界** | **+69.80** | 46.9% | −48.3 |

**修了少赚 0.96R。** 因为新仓按 5 根确认要比 2 根慢，多扛的几根 K 线里
有一部分被硬止损打掉。**这个代价认了** —— 规矩和界面必须一致，
否则卡片上写 0/2、代码按 5 根跑（或反过来），谁看都会懵。

半仓本来就在第③条段 B 的 0.8R 保护下，再叠一层回撤条件等于**双重收紧**，
把还能继续跑的趋势单提前放走。

注意 ⓑ 单独开是 +65.77R，只比 K5 的 +67.61R 低 1.84R —— 它本身不算坏，
真正拖累组合的是 ⓐ（回撤 50% 在额外浮盈小时门槛只有零点几 R，过于敏感）。

**浩哥后续那句「③不变，只加一条再满 2R」被数据完整印证。**

### 三个条件各自的准确语义

| 条件 | 参数 | 算法 | 默认 |
|---|---|---|---|
| ⓐ 半仓额外浮盈回撤 50% | `half_dd_pct` | `(峰顶 − 当前) ≥ (峰顶 − 平半价) × 0.5` | **关（0）** |
| ⓑ 半仓峰顶回撤固定 0.8R | `half_dd_r` | `(峰顶 − 当前) ≥ min(0.8, 峰顶 − 平半价)` | **关（0）** |
| ⓒ 半仓再赚满 2R | `half_tp_r` | `(当前 − 平半价) ≥ 2.0` | **开（2.0）** |

**⚠ 门槛必须按「平半之后新赚的那一段」算，不能从开仓算。**
从开仓算的话：峰顶 3.0R 回撤 50% = 1.5R → 出场落在 **1.5R**，
比平半价 2.0R 还低 —— **等于把已经落袋的一半又吐回去**。
按额外段算：峰顶 3.0R，额外 1.0R，回撤 0.5R → 出场 2.5R，永远高于平半价。

**ⓑ 的语义澄清（曾被误判为缺陷，已修正）**：

半仓是**独立的一段**，R 从平半那一刻重新起算。半仓赚 0.5R 就是赚 0.5R，
回撤 0.8R 就是回撤 0.8R —— **与已经落袋的那一半没有任何关系**，
那半在平仓那一刻就已经结算完成，后面的价格怎么走都动不了它。

例（1R = 150U）：
```
开仓 → 2.0R：平掉一半，落袋 +1.0R = +150U（已结算，锁死）
半仓涨到 2.5R：半仓额外 +0.5R
跌到 1.7R：半仓峰顶回撤 0.8R → 条件②触发
  半仓这一段：2.0 → 1.7 = −0.3R，×50% 仓位 = −0.15R = −22.5U
  整体账户：+150 − 22.5 = +127.5U  ← 仍然净赚，不存在"倒吐"
```

半仓只赚 0.5R 时这条不会触发 —— 总共才赚 0.5R，哪来的 0.8R 可回撤。
**它本来就该等，不是缺陷。**

### 一次误判的完整记录（2026-11-06 23:5x）

**我先把这条判成了 BUG**，理由写的是「峰顶 2.5R 时按 0.8R 回撤出场落在
1.70R，比平半价低，等于把已落袋的一半又赔回去」，并加了夹取
`hr = min(hr, 峰顶 − 平半价)`。

**浩哥一句话点破**：「这个我不是说用半仓后的基数重新计算么，为啥还会
牵扯到已经平掉的那一部分」。

**他说得对 —— 我把「半仓」和「整体账户」混成了一件事。**
夹取的实际效果是「半仓最多跌回平半价就走」，属于提前出场，
回测证明它反而更差：

| 方案 | 夹取版 | 撤回后 | 差 |
|---|---|---|---|
| K5 + 回撤 0.8R | +55.02R | **+65.77R** | **+10.75** |
| K5 + 三条件全开 | +56.19R | **+62.03R** | +5.84 |

**教训：判断一段逻辑是不是 BUG，先确认它的"基准"是什么。**
半仓有自己独立的账本，拿整体账户的眼光去看它，必然误判。

## 六、自检结果（`check_k5.py`）

**44 项全部通过。** 覆盖：

1. **参数链路** —— yaml 里 10 个出场参数逐项对照期望值
2. **公式复算 vs API 实际返回** —— 每笔实时持仓的 `trail_target_r` / `trail_is_pct` / `ma_confirm_bars` 与按源码公式重算的值完全一致
3. **边界条件** —— `peak = 0 / 0.04 / 0.05 / 0.06 / 0.4 / 1.0 / 1.6 / 1.99 / 2.0 / 2.5 / −0.5`
4. **门槛单调性** —— 分段内单调；护栏区（`peak ≤ 0.05`）与比例区之间有落差，是护栏的必要代价
5. **半仓门槛不倒吐** —— 五个峰顶档位逐一验证出场价 ≥ 平半价
6. **代码残留扫描** —— 半仓分支无裸常量（门槛必须来自 `_p()`）、`peak` 在首次使用前已定义、前端读 `trail_target_r` 而非写死 0.8

## 九、给下一位接手的人

1. **第③条不是一个阈值，是两个。** 改 `trail_r` 只影响峰顶 ≥2R 的仓位；
   峰顶不足 2R 的走 `trail_pct`。**别只改一个就以为改完了。**
2. **峰顶必须落库。** 它是 K5 的门槛来源，只存内存等于给全仓埋一颗雷。
3. **门槛必须按「平半后新赚的那段」算。** 从开仓算就会掉到平半价下面。
4. **想让它「早点止损」的所有直觉方案都试过了，全更差。** 保本止损、
   调小 trail_r、回撤超标强平 —— 数据在本文第二节。这策略的钱是靠
   「282 笔小亏换 316 笔大赚」赚的，砍小亏等于砍大赚。
5. **真正能改善的是入场质量，不是出场。** 282 笔倒亏单里，190 笔峰顶
   连 0.5R 都没摸到 —— 问题在开仓那一刻就注定了。
