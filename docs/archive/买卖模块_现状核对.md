## A. 入场 —— 现在实际跑的顺序

每根 **15 分钟** K 线收盘后，对监控池里每个币依次检查：

| 序 | 检查项 | 条件 | 不过就 |
|---|---|---|---|
| A1 | 已有同策略持仓？ | `ctx.has_position(sym, sid)` | 跳过该币 |
| A2 | K 线够不够？ | `len(ks) >= max(ce_len, z_len*2, swing_lb, 100) + 80` = **180 根** | 跳过 |
| A3 | 算指标 | CE(1×2) / ZLSMA(50) / ATR / 布林带宽度 | — |
| A4 | 这根 K 线评估过没？ | `_LAST_BAR[(sid,sym)] == bar_ts` | 跳过（防重复出信号） |
| A5 | **① CE 方向翻转** | `dir[i] != dir[i-1]` | 跳过 |
| A6 | ② ATR 门槛 | `min_atr_pct = 0` → **已关闭** | — |
| A7 | **③ BBW 分位 > 70%** | `bbw_pct[i] >= 70`（近 100 根分位，15m） | 跳过 |
| A8 | **④ HA 关键 K 线** | 多：`HA收盘 > ZLSMA 且 HA收盘 > HA开盘`；空镜像 | 跳过 |
| A9 | 算价 | 见 B 节 | — |
| A10 | 风险过滤 | `risk/px*100 > 30%`（止损太宽） | 跳过 |
| A11 | 出信号 | 带上 stop_price / take_profit / max_hold_sec | 开仓 |

### ⚠️ A7 和 A8 的顺序问题（待你拍板）

- **我告诉你的顺序**：① CE → ② HA → ③ BBW
- **代码实际顺序**：CE → ~~ATR~~ → **BBW** → **HA**
- **三道光闸诊断表也按「CE → HA → BBW」显示**

**后果**：一个币 HA 形态不对、BBW 也不达标时，诊断表会说「HA形态不对」，
但代码其实是先卡在 BBW 上。**页面显示的卡点可能和代码真实卡点不一致。**

（逻辑上两种都"不会开仓"，结论一样；但诊断会误导你判断该调哪道闸。）

**修法**：把代码里 BBW 的判断挪到 HA 后面，让代码顺序 = 诊断顺序 = 你理解的顺序。
改动很小（两段 continue 换位置），逻辑完全等价，不影响任何交易结果。

## B. 价格口径（"方案 B" —— 2026-11-06 定案）

**一句话：「平均K线看路，真实价算钱。」**

| 用途 | 用哪个价 | 代码 |
|---|---|---|
| 判方向（多空、站没站上均线） | **HA 合成价** | `use_ha: true` |
| CE 棘轮止损线 | **HA 序列算的 ATR** | `_ce_zlsma(..., use_ha=True)` |
| **入场价（信号价）** | **真实收盘价** | `px = ks[i]["close"]` |
| **止损价** | **真实 K 线 20 根阶段低点/高点** | `min(ind["low_raw"][...])` |
| **止盈价** | 信号价 ± 风险 × 1.2 | `tp = px ± risk * rr` |

**为什么入场必须用真实价**：HA 的收盘价是合成的，实盘压根成交不了。
LIT 那笔就是教训 —— HA 收盘 3.4170 vs 真实收盘 3.4530（差 2.11%），
盈亏比从 1.20 掉到 0.73。

**已知副作用（不是 bug）**：允许滑点后 RR 会偏离 1.2 ——
空单成交更高 → RR 变大（XMR 1.83）；多单成交更高 → RR 变小（LIT 0.73）。
**如实记录，不修正。**

## C. 出场 —— 四条并列，谁先满足谁全平

**检查频率：每 0.5 秒一次**（`LOOP_SEC`），由 `engine.py` 统一检查。

**优先级顺序（代码实际顺序）：**

| 序 | 出场 | 触发条件 | 谁检查 |
|---|---|---|---|
| **C1** | **时间止损** | `now - opened_at >= max_hold_sec`（**16 小时**） | `engine.py:106` |
| C2 | 策略时间出场 | `now >= time_exit_at`（S15 未用） | `engine.py:108` |
| C3 | 移动止损 | `trail_atr`（**S15 未传，不触发**） | `engine.py:110` |
| **C4** | **止损** | 多：`price <= stop_price`；空：`price >= stop_price` | `engine.py:124` |
| **C5** | **止盈** | 多：`price >= take_profit`；空：`price <= take_profit`（1.2R） | `engine.py:128` |
| **C6** | **破均线回撤** | 三个条件同时满足：<br>① HA 收盘破 ZLSMA<br>② **连续 2 根** K 线都破<br>③ 从**持仓期峰顶浮盈**回撤 **≥ 0.8R** | `strategies.py:848` |

### 几个细节（容易理解错的地方）

**① 时间止损排在最前面。**
如果第 16 小时那一瞬间同时触发了止损，会记成「达到最长持仓时限」而不是「止损触发」。
**不影响盈亏，只影响出场原因的统计标签。**

**② C6 的「回撤」是从峰顶算，不是浮盈门槛。**
你之前纠正过这一点：应该看「从赚最多的那个点掉下来多少」，
而不是「赚够了多少才允许平」。
代码里 `st["peak"]` 记录持仓期 `cur_r` 最大值，`drawdown = peak - cur_r`，
`drawdown >= 0.8` 才平。**方向是对的。**

**③ C6 的「连续 2 根」只在 K 线边界更新计数。**
`st["cnt"]` 只在 `bar_ts` 变化时 +1 或清零，不会因为盘中反复穿越而抖动。

**④ C6 在亏损时不触发（因为 drawdown 需要 peak ≥ 0.8R）。**
这是设计如此 —— 亏损单让止损说话，盈利单才谈保护利润。
回测证据：亏损就跑的版本 1717 次触发，光手续费吃 97R。

## E. 执行 —— ⚠ 这里有一处口径不符，要你决定

### 现在的实际情况

```
回测口径：maker 0.02% + 零滑点  → 假设限价挂单能成交
line 线上记账：fee_rate=0.0002, slip_pct=0  → 用同一套口径
真实下单：executor 用【信号价】直接成交，没有挂单撮合
```

```python
# executor.py:117-121
_slip = config.PAPER_SLIPPAGE if sig.slip_pct is None else sig.slip_pct   # = 0
_fee_rate = config.PAPER_FEE_RATE if sig.fee_rate is None else sig.fee_rate # = 0.0002
slip = 1 + _slip  # = 1.0
fill = price * slip  # = 信号价
fee = fill * qty * 0.0002  # maker 费率
```

### 问题在哪

| | 现在记的账 | 真实市价单会是 |
|---|---|---|
| 成交价 | 信号价 | 当时的市价（可能差 0.1~0.5%） |
| 费率 | **maker 0.02%** | **taker 0.05%**（2.5 倍） |

**这意味着 paper 盘的盈亏是乐观的。**

回测里差这 0.03% 有多大？成本对比（2909 笔同规则）：

| 费率 | 每笔费用 | 净R |
|---|---|---|
| 市价 taker 0.05% + 滑点 | 0.0525R | **−94.88R** |
| **maker 0.02% + 零滑点** | 0.021R | **+8.02R** |
| 完全免费 | 0 | +54.49R |

**光费率口径就能把 +8R 变成 −95R。**

### 三个选择

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 保持现状（推荐观察期内）** | paper 按 maker 记账，等观察期结束后实现真实限价挂单 | 观察期数字偏乐观，但和回测可比 |
| B. 立刻改成 taker 0.05% 记账 | 改 `fee_rate: 0.0005` | 数字变真实，但和回测（maker）不可比，观察期基线要重算 |
| C. 现在实现真实限价挂单 | 改 executor，挂 post-only 单，超时未成交撤单 | 工作量大，观察期要重来 |

**我的建议：A。** 理由是观察期的目的是验证"策略逻辑对不对"，不是验证"成本多少"。
成本这关等真实限价挂单做完再一起算。但**你必须知道这个数字是乐观的**，
别看到 +50U 就以为实盘也能赚 50U。
