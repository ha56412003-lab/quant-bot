## 二、315 处低对比度的真实构成

**这是本次最重要的发现**：315 处里 313 处是同一类东西，不是 315 个散落的问题。

| 选择器 | 数量 | 原色 | 对比度 | 判定 |
|---|---|---|---|---|
| `.ant-tag.ant-tag-green` | **279** | `rgb(56,158,13)` | **3.37:1** | ❌ 差 1.13 |
| `.ant-tag.ant-tag-cyan` | 26 | `rgb(8,151,156)` | **3.39:1** | ❌ 差 1.11 |
| `.ant-tag.ant-tag-gold` | 8 | `rgb(212,136,6)` | **2.76:1** | ❌ 差 1.74 |
| `.sub`（净值下方说明） | 2 | `rgb(111,110,104)` | 4.36:1 | ⚠️ 差 0.14 |
| `.btn` | 1 | 同上 | 4.36:1 | ⚠️ |

**根因**：antd 的 `<Tag>` 预设色（green/cyan/gold）是按**纯白底**调的，放到纸白 `#eeede8` 上就掉到 3.3 左右。
它们在深色主题下是"实心亮色块"，看不出问题；纸面模式下变成"浅色底 + 亮色字"，直接失效。

## 六、可复用的体检脚本

保存在 `preview/audit_theme.js`，用法：

```js
// 在浏览器控制台执行
// 返回 {pink:[], dark:[], low:[]}
// pink  = 玫红系元素（R>150, G<130, B>90, R-G>60）
// dark  = 深色背景（亮度<100，纸面模式下应人工确认是否刻意保留）
// low   = 文字对比度 <4.5:1 且字号 <18px（WCAG AA 不达标）
```

**以后新增页面或改样式后，跑一遍这个脚本就能自查**，不用再靠眼睛找。

## 七、踩坑记录

1. **深色主题的"高级灰"在浅色主题下会失效**
   深色下大量用 1.35:1、4:1 的低对比度灰做层次，人眼看不出问题；换到白底全部变成"看不见"或"勉强能看"。

2. **CSS 类选择器优先级高于全局伪元素**
   `html[data-theme="paper"] ::-webkit-scrollbar-thumb`（0,1,1）打不过
   `.pnl > div:last-child::-webkit-scrollbar-thumb`（0,2,1）—— 必须逐个点名。

3. **antd 的 darkAlgorithm 是 JS 层算出的 CSS 变量，纯 CSS 改不动**
   必须在 `ConfigProvider` 的 `theme.algorithm` 里切。这是"卡片一直是深色"的根本原因。

4. **同一视觉层在不同主题下需要不同的色阶**
   原来 body `#eeede8` / stage `#e9e8e2` 差 5 个色阶，深色下是层次感，纸白下是补丁。

5. **`vision_analyze` 会把深红认成玫红**
   机械判定（RGB 阈值）比视觉判断可靠。所有色值结论以 `getComputedStyle` + WCAG 公式为准。
