## P0-1　交易所拒单/部分成交，系统当成功 → 裸仓【实证】

`backend/executor.py:232`

```python

db.close_position(pid, fill, pnl, reason)                                # ← 标记已平
```

对照开仓路径 `:167-179` 是认真解析 `avgPrice`/`executedQty` 的 —— **平仓这条路忘了。**

`tests/audit_live_close.py` 实测：

```
场景 1 交易所拒单（返回 None）
  ✗ close_position 返回 True     ← 系统以为平掉了
  ✗ 本地剩余仓位 0 个            ← 实际交易所有仓

**后果**：交易所因余额不足/精度/限频/网络返回空，代码连看都不看。

    return False
fill = float(order.get("cummulativeQuoteQty") or 0) / exec_qty   # 真实成交均价
if exec_qty < qty - 1e-9:
    # 部分成交：按真实数量记账，剩余留在仓位上
    ...
```

### P1-16　切换执行交易所无持仓保护 → 平仓打到错的交易所【代码】

### P1-18　NaN 能穿透 `qty/price > 0` 校验【实证】

`backend/risk.py:149,164-170` + `executor.py:119-120`
