## 零、一句话总览

```
候选池 200 个币
      ↓ 四道闸 + 滞回，每分钟重算
监控池 40 个币
      ↓ 每 15 分钟扫一次，六道进场闸
策略信号
      ↓ 九道风控闸 + 仓位计算
开仓（paper / 实盘）
      ↓ 每 0.5 秒判一次，七条出场
平仓
```

一句话：**池子决定「能看哪些币」，进场闸决定「现在能不能买」，风控闸决定「买了会不会把账户搞死」，出场决定「什么时候走」。**

## 一、入监控池

### 1.1 候选池（200 个）

| 项 | 值 | 决定者 |
|---|---|---|
| 容量 | 200 | `strategies.yaml` → `pools.candidate.size` |
| 刷新频率 | 每 3 小时 | `pools.candidate.refresh_hour` |
| 振幅下限 | 24h 振幅 ≥ 10% | `min_amp_pct` |
| 振幅上限 | 24h 振幅 ≤ 300% | `max_amp_pct` |
| 成交量窗口 | 近 30 天 | `vol_days` |
| 白名单 | BTC / ETH 永远在 | `whitelist` |

候选池是「宇宙」，只在里面挑监控池，不直接交易。

### 1.2 监控池（40 个）—— 四道闸 + 滞回带

**这是核心。进池和出池用的是两条不同的线，中间留一条「不动」的缓冲带。**

| # | 条件 | 进池门槛 | 出池门槛 | 决定者（代码） |
|---|---|---|---|---|
| ① | 24h 成交额 | ≥ **500 万 U** | < **500 万 U** | `quality.MIN_QUOTE_VOL = 5e6` |
| ② | 插针风险 | 单根振幅÷ATR ≤ **8.0** | > **8.0** | `quality.MAX_SPIKE = 8.0` |
| ③ | **止损距离** | ≥ **1.00%** | < **0.85%** | `quality.STOP_MIN_PCT / STOP_EXIT_PCT` |
| ④ | **趋势效率 EFF** | ≥ **0.30** | < **0.25** | `quality.EFF_MIN / EFF_EXIT` |

**①②没有滞回（同一把尺子进出），③④有滞回（进出两条线）。**

为什么要滞回：止损距离在 0.99% 和 1.01% 之间抖动时，如果用一条线，币会每 60 秒进出池一次，
策略扫描跟着疯抖。留一条 15% 的缓冲带，只有明显变差才踢出去。

### 1.3 两个关键指标怎么算

**止损距离**（`quality._stop_dist`）

```
做多距离 = (现价 − 前 20 根最低价) / 现价 × 100
做空距离 = (前 20 根最高价 − 现价) / 现价 × 100
止损距离 = max(做多距离, 做空距离)
```

取 max 的理由：只要有一个方向的止损够宽，这个币就值得监控。
用的是**原始 K 线的 high/low**，不是 Heikin-Ashi 合成价 —— 与策略止损同口径。
窗口 20 根 15m = 5 小时，参数从 `strategies.yaml` 的 `swing_lookback` 读，不硬编码。

**趋势效率 EFF**（`quality._eff`，Kaufman 1995）

```
振幅 = (96 根内最高 − 最低) / 最低
EFF  = |末价 / 首价 − 1| ÷ 振幅
```

窗口 96 根 15m = **24 小时**。

| EFF | 含义 | 进不进池 |
|---|---|---|
| ≥ 0.55 | 单边趋势 | 进 |
| 0.30 ~ 0.55 | 半趋势 | 进 |
| 0.25 ~ 0.30 | 模糊地带 | **滞回区，看它原来在不在** |
| < 0.25 | 宽幅震荡 | 出 |

**★ 铁律：行情分类禁止用「24 小时涨跌幅」，必须用 EFF。**
涨跌幅衡量「从哪到哪」，EFF 衡量「这段路走得直不直」。同样涨 5%，一路涨上去和来回震荡后
回到 5%，涨跌幅一样但可交易性天差地别。

### 1.4 平滑与保护

| 机制 | 值 | 作用 | 决定者 |
|---|---|---|---|
| 平滑窗口 | 5 分钟取中位数 | 防止单次采样抖动导致进出池 | `quality.SMOOTH_SEC = 300` |
| 最短停留 | 进池后 **15 分钟**内不因变差被踢 | 防止分钟级反复进出 | `quality.MIN_DWELL_SEC = 900` |
| 刷新节拍 | 每 60 秒 | 池子重算频率 | `quality.REFRESH_SEC = 60` |
| 容量 | **40** | 池子上限 | `quality.MONITOR_SIZE = 40` |

### 1.5 补位规则（重要）

```
已留下的优先，剩余名额按成交额从高到低补
```

`quality.py:550-556`。意思是：**已经在池里的币不会被一个新来的、成交额更大的币挤掉。**
只有当池子没满时，新币才能进来。

这保证了池子的稳定性，代价是「更优的币可能进不来」—— 已知取舍，不改。

### 1.6 池子空了会怎样

**fail-closed：直接拒绝开仓。**

`quality.is_tradable` 返回 `(False, "监控池为空")`。以前是「空池放行全部候选币」，
2026-11-09 改成拒绝 —— 池子空说明数据链路或配置出问题了，这时候从 200 个币里随便开仓
比不交易危险得多。

### 1.7 持仓中的币不特殊对待

池子重算时，**持仓的币该踢就踢**（2026-11-08 浩哥定）。
理由：出场由 `engine.manage_positions` 独立负责，跟池子在不在没关系。把持仓币锁在池里
只会占名额、扰乱排序。

## 二、开仓

### 2.1 触发时机与扫描对象

| 项 | 值 | 决定者 |
|---|---|---|
| 扫描节拍 | 每 15 分钟（K 线收盘后） | `scan_interval: 15m` |
| 扫描对象 | **只扫监控池 40 个币**，不扫全候选池 | `Ctx(universe, quality.monitor_list())` |
| 每根 K 线判定次数 | 每币每根只判一次（去重） | `_LAST_BAR` |
| 品种去重 | 同币已有仓位 → 跳过（禁止对锁/加仓） | `risk.allow_entry` |

### 2.2 六道进场闸（`strategies.S15CeZlsma.evaluate`）

**必须六道全过，少一道都不开仓。**

| # | 闸门 | 条件 | 参数 / 决定者 |
|---|---|---|---|
| ① | **CE 翻转** | Chandelier Exit 方向翻转，且收盘站到 ZLSMA50 同侧 | `ce_len: 1` / `ce_mult: 2.0` / `use_close: true` |
| ② | **HA 形态** | HA 阳线（收>开）且收在 ZLSMA 之上；做空反之 | `use_ha: true` |
| ③ | **BBW 分位** | 布林带宽度分位 ≥ **70%** | `bbw_pct_min: 70.0` |
| ④ | **偏离闸** | 进场价离 ZLSMA ≥ **0.5%** | `min_dev_pct: 0.5` |
| ⑤ | **止损距离上限** | 止损距离 ≤ **5%** | `max_risk_pct: 5.0` |
| ⑥ | **池子资格** | 在监控池内 + 成交额/插针达标 | `quality.is_tradable` |

**① 是事件型闸门**：只在 CE 方向翻转的那一根触发，不是「一直满足就一直买」。
这就是为什么 S15 一天开不了几单 —— 它在等翻转。

**③ ④ 是一对互补闸**：③ 要求波动够大（值得做），④ 要求价格已经走进去了（不是贴均线磨）。
④ 是 2026-11-09 补进回测的那道 —— 之前回测漏了它，多开 109 笔。

**⑤ 是 2026-11-09 从 30% 收到 5% 的**，依据是实盘 80 笔：止损距离 3~5% 那段赚 +257.81U，
≥5% 那段亏 −118.78U。

### 2.3 止损价怎么定

```
做多：止损 = 前 20 根原始 K 线的最低价
做空：止损 = 前 20 根原始 K 线的最高价
```

参数 `swing_lookback: 20`（15m × 20 = 5 小时窗口）。
`quality._swing_lb()` 运行时从 yaml 读 + mtime 缓存 + 失败回退 20，**不硬编码**。

开仓时把止损价写进 `positions.stop_price`，之后由 `engine.manage_positions` 每 0.5 秒比对。

### 2.4 九道风控闸（`risk.allow_entry`，按代码顺序）

**任何一道不过就放弃这一单，不是延后重试。**

| # | 闸门 | 条件 | 参数 |
|---|---|---|---|
| ① | **日熔断** | 当日已实现亏损 ≥ 净值 10% → 全停 | `daily_loss_halt_pct: 10.0` |
| ② | **日目标** | 当日已实现盈利达 500U 并维持 30 秒 → 停止开新仓 | `daily_target` |
| ③ | **事件静默** | 重大事件前后 30 分钟不开仓 | `event_quiet_minutes: 30` |
| ④ | **同币去重** | 该币已有仓位 → 拒绝（禁止对锁/加仓） | — |
| ⑤ | **并发币数** | 同时在仓币数 ≥ **8** → 拒绝 | `max_concurrent_coins: 8` |
| ⑥ | **同向上限** | 同方向仓位 ≥ **6** → 拒绝 | `max_same_side: 6` |
| ⑦ | **总敞口** | 所有仓位名义价值 ÷ 净值 ≥ **6 倍** → 拒绝；**任一在仓币取不到价 → 也拒绝** | `max_gross_leverage: 6` |
| ⑧ | **浮亏闸** | 当前浮亏 ≥ 净值 **8%** → 暂停开新仓（已有仓位照常管理） | `unrealized_halt_pct: 8.0` |
| ⑨ | **策略资金** | 该策略分配的资金已用满 → 拒绝 | `_strategy_capacity` |

**⑦ 的 fail-closed 是 2026-11-06 修的**：以前断线时所有仓位算出「0 敞口」，这道闸静默消失，
可以一路开满仓。现在拿不到价就拒绝。

**⑧ 是 2026-11-09 新增的**：日熔断只看**已实现**亏损，8 个仓位各浮亏 1R 时系统依然认为
「今天没亏」，继续加仓；等止损全部落地，亏损已经发生。浮亏闸只管「不再加新风险」，
不减仓不强平，且**不落库不过夜** —— 价格反弹回来自动恢复。

### 2.5 仓位怎么算（`risk.position_qty`）

```
目标风险额 = 净值 × risk_per_trade_pct(%)     → 1.5%
数量 = 目标风险额 ÷ (入场价 − 止损价)
名义上限 = 净值 × max_position_pct_per_coin(%)  → 32%
杠杆上限 = leverage                            → 6x
取三者最小值
```

所以：**止损距离越宽，仓位越小**；止损距离 5% 时，1.5% 风险额对应的仓位会被名义上限
（32%）截断。这就是为什么「不改单币上限，光调风险比例没用」。

### 2.6 信号排序与择优

```
signals.sort(key = -(strength / (1 + 0.3 × fresh)))
```

`strength` 是信号强度，`fresh` 是翻转后过了多少根。**强度高且新鲜的优先。**
避免「列表顺序先到先得」把有限的 8 个仓位额度浪费在磨了很久的老信号上。

## 三、出场

### 3.1 两层判定，每 0.5 秒一轮

**第一层 `engine.manage_positions`（按代码顺序，先判先出）：**

| 顺序 | 判定 | 条件 | 参数 / 决定者 |
|---|---|---|---|
| 1 | **16h 强平** | 持仓 ≥ 16 小时，**无条件**（平半后照样平） | `max_hold_hours: 16` → `max_hold_sec: 57600` |
| 2 | 策略时间出场 | `time_exit_at` | S15 不给值 → **跳过** |
| 3 | 移动止损 | `trail_atr`（Chandelier 价格距离） | S15 给 0 → **跳过** |
| 4 | **硬止损** | 实时价触及开仓时算好的 `stop_price` | `swing_lookback: 20` |
| 5 | 止盈 | `take_profit` | S15 给 0.0 → **跳过** |

**第二层 `strategies.check_exit`（上面都没触发才进）：**

| 顺序 | 判定 | 条件 | 参数 |
|---|---|---|---|
| ⓪ | **快速失败** | 满 **4 小时** 且峰顶 R < **0.5R** → 全平 | `quickfail_hours: 4.0` / `quickfail_min_r: 0.5` |
| ① | **平一半** | 峰顶 R ≥ **1.8R** → 平一半 | `half_at_r: 1.8` |
| ② | **3R 全平** | 已平半 且 现价 R − 1.8 ≥ **1.0** | `half_tp_r: 1.0`（带 1e-9 容差） |
| ③ | **移动止盈** | 已平半 且 峰顶 ≥ **1.5R** 且 峰顶 − 现价 ≥ **1.2R** → 平剩余 | `trail_arm: 1.5` / `trail_dd: 1.2` |
| ④ | **镜像出场** | CE 翻转 **＋** HA 反向 K 线站错边 **＋ BBW 分位 ≥ 70** | `mirror_bbw_min: 70.0` |

**另外还有一条全局的：日目标全平** —— 当日盈利达 500U 并维持 30 秒 → 平掉所有仓位
（在 `daily_target.tick` 里，与上面的通道独立）。

### 3.2 每条为什么这么定

**16h 强平（无条件）**
长尾的根源是「平半豁免」—— 平半后按半仓继续跑，能跑到几十小时。2026-11-09 定：16 小时一刀切，
平半了也照平。代价是丢掉少数慢牛，收益是持仓时间封顶、资金周转可预测。

**硬止损（20 根摆动）**
开仓时算好，写进库，之后不再变。窗口从 20 缩到 8 会把止损从 2.30% 收到 2.06%，
但回撤从 −25.0 恶化到 −33.4 —— 不值，所以保持 20。

**快速失败（4h / 0.5R）**
「4 小时了还没赚到半个 R，说明这单进错了」。它和时间止损在抢同一件事 —— 都在解决「烂单别拖」，
但快得多。2026-11-09 审计发现回测里完全没有这条，导致结论反转过一次。

**平一半（1.8R）**
1.8R 达成率只有 21.7%，市场侧 12h 内顺向 ≥3.9% 的机会只占 20.0% —— **已经贴着物理上限**，
所以不能再降门槛（降了就是把大肉砍光），也不能再提高（提了几乎打不到）。

**3R 全平（平半后再赚 1R）**
平半之后再吃 1R 就全平。回测对比：留着它 +94.2R，关掉它 +87.5R —— **两条并存更好**。

**移动止盈（1.5 武装 / 1.2 回吐）**
语义是**相对回撤**不是绝对落袋：峰值 3R 时平在 1.8R，峰值 5R 时平在 3.8R。
只在平半之后启用。实测剩余半仓落袋中位 1.63R、实际回吐中位 1.20R（15m K 线会跳空穿过 1.2R）。

**镜像出场（加 BBW ≥ 70）**
判定「趋势反转了没有」：CE 翻向另一边 + HA 出现反向 K 线站到 ZLSMA 错误一侧。
**BBW 门槛是 2026-11-09 加的**：CE 是 ATR 通道，低波动时价格来回穿，翻转极频繁 —— 那是噪音。
不带门槛时镜像出场占全部出场的 43%、均笔 −0.08R（在震荡里被反复扫）；加 ≥70 后降到 15%，
那些单子改走时间止损和移动止盈，反而赚钱。8 仓并发下净收益 +55.4R → +71.4R，回撤 −21.3 → −19.4。

### 3.3 判定时刻的一个已知偏差

| | 线上 | 回测 |
|---|---|---|
| 判定频率 | 每 0.5 秒 | 每根 15m 收盘 |
| 指标取值 | 上一根已收盘指标 + 当根实时价 | 当根收盘统一判 |

**线上会比回测早一根 K 线出手。** 方向上实盘可能更差（更早被噪音打出去），
但用 15m 数据量化不了这个差异，需要 1m 数据。这是已知的、被接受的保守预期。
