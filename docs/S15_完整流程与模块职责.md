## 三、入场三关（现在在跑的，实际条件）

### 第 ① 关 · 监控池（`quality.py`）

**2026-11-08 重构：ATR 退出监控池，换成「止损距离 + 趋势效率」。**

| 道 | 条件 | 参数 | 现值 |
|---|---|---|---|
| 1 | **止损距离**（20 根 15m 摆动低/高点到现价） | `stop_min_pct` / `stop_exit_pct` | 进 ≥ 1.00% / 出 < 0.85% |
| 2 | **趋势效率 EFF**（96 根 15m 净位移 ÷ 振幅） | `eff_min` / `eff_exit` | 进 ≥ 0.30 / 出 < 0.25 |
| 3 | **插针幅度**（96 根 1h 最大单根 ÷ 1h ATR） | `max_spike` | ≤ 8.0 |
| — | 24h 成交额 | `min_quote_vol` | ≥ 500 万 U |
| — | 停留时长 | `min_dwell_sec` | ≥ 900 秒（15 分钟） |
| — | 容量 | `size` | 40 个 |
| — | 刷新频率 | `refresh_sec` | 60 秒（增量拉最新 2 根） |
| — | 平滑 | `smooth_sec` | 两个指标各取 5 分钟中位数 |

**为什么换掉 ATR —— 实测筛反了：**
```
200 币按 ATR>0.40% 分组：
  进池 50 个 → EFF 中位 0.387、42% 是横盘(EFF≤0.30)
  被拦 150 个 → EFF 中位 0.525、21% 是横盘
→ 进池那组趋势效率反而低 36%，ATR 筛出来的恰恰是更没方向的币。
```
**根因：ATR 测「跳得狠不狠」，不测「有没有方向」；排横盘是 EFF 的活。**
**而手续费安全线（ATR 原本想管的）用止损距离更直接：止损 1.0% 时手续费恰占 1R 的 10%。**

**滞回 + 平滑的作用：**
```
不平滑：止损距离每分钟抖 0.033%，从 1.00 掉到 0.85 只要 4.5 分钟
        → 27% 的币刚进 5 分钟就被踢出去
5 分钟中位数：刚进就出降到 1%，每币进出 6.5 次/75 小时，停留中位 32 分钟
```

**实测落地（2026-11-08 17:37）：监控池 36 个 / 容量 40，全部达标：**
```
止损 ≥1.0% ✅   EFF ≥0.30 ✅   插针 ≤8.0 ✅   成交额 ≥500万 ✅
池外 164 个被拦原因：止损不够 53 / EFF 不够 50 / 成交额或插针 50 / 两者都不够 11
```

> ⚠️ **CE 的 ATR 不在这个文件里** —— `strategies.py` 的 `_rma(tr, ce_len=1)` 是
> Chandelier Exit 的保护线，**去掉它就不是 S15 了**。监控池这次只换入口筛子。
>
> ⚠️ `atr_enter_min` / `atr_exit_max` / `atr_interval` 三个参数仍在 yaml 里，
> 但**已停用**（仅保留供回滚）。`snapshot()` 返回 `atr_enabled: false`。

### 第 ② 关 · 开仓信号（`strategies.py:324` 起）

五条件必须同时成立，都发生在**同一根已收盘 15m K 线**上（`i = len(ks) - 2`）：

| ⑤ | **进场价离 ZLSMA50 至少 0.5%**（2026-11-08 新增） | `min_dev_pct` | 0.5（写 0 = 关闭） |

> ⑤ 为什么加：60 天回测里，偏离 ≤0.5% 才进场的 104 笔净 −14.8R / 胜率 34.6% / **止损率 51.9%**；
> 偏离 >0.5% 的 640 笔净 +90.9R / 胜率 47.8% / 止损率 31.7%。被挡组止损率是留下组的 1.6 倍 ——
> 贴着均线开仓，说明根本没走出距离，止损太近，一碰就碎。

**做空**：`dir` 由 +1 翻 −1，且 HA收盘 < ZLSMA 且 HA收盘 < HA开盘

止损价 = **20 根摆动低点/高点**（`swing_lookback: 20`，用原始 K 线真实价格，不用 HA 合成值）

## 五、两个 0.5 秒循环在干什么

### `position_loop`（管出场）

```
每 0.5 秒：
  1. 取所有持仓
  2. 拿实时标记价（WebSocket）—— 拿不到 → 记缺价告警（限频 60s，60s 后升级 error）
  3. 更新 MFE / MAE（最大浮盈 / 最大浮亏）
  4. 按顺序判：时间止损 → 策略时间 → 移动止损 → 硬止损 → 止盈 → check_exit
  5. 命中就平仓（失败 30 秒退避，防 live 下疯狂重复下单）
```

### `scan_loop`（管开新仓）

```
每 0.5 秒：
  1. 每 10 秒：算净值 → 写净值曲线 → 日内熔断检查 → 日目标状态机
  2. 每轮：拉所有到期的因子
  3. 监控池没就绪 → 先不扫（超过 5 分钟才放行）
  4. 每个策略按自己的 scan_interval 判断该不该算（S15 = 15m）
  5. 算出的信号按「强度 / (1 + 0.3×新鲜度)」排序 —— 强信号、新信号优先
  6. 逐个过 quality.is_tradable → risk.allow_entry → 影子记录 → 下单
```

**重要**：`engine.py:178` 和 `:197` **每 0.5 秒重读一次 `strategies.yaml`**
→ **改配置立即生效，不用重启服务。**（改 `.py` 代码才需要重启）

### 4 项需注意的

| 项 | 状态 | 说明 |
|---|---|---|
| `rr_ratio: 1.2` | ⚠️ 半死 | 只用于算 `tp` 变量做合法性校验（`tp > 0`），实际 `take_profit=0.0` 落库，**不参与平仓**。改它不改变行为。 |
| `min_atr_pct: 0` | ✅ 关闭 | yaml 写 0 = 关闭策略层 ATR 门槛。ATR 判断已移到池子层 5m 双档。 |
| `slip_pct: 0.0` | ✅ 为零 | 滑点 0，只影响记账成本口径，不影响成交。 |
| `daily_target.auto_close_sec: 5` | ⚠️ 风险 | 提醒发出 **5 秒**即强制全平 + 当天停开仓。来不及人工反应。 |

### 3 个 `0` 是"继承语义"不是 bug

| 参数 | 写 0 的含义 |
|---|---|
| `capital_usd: 0` | 用账户实时净值 |
| `max_position_usd: 0` | 用 `capital × leverage` |
| `risk_per_trade_pct: 0` | 用全局的 1.5% |

> ⚠️ **陷阱**：想真的把某参数设成 0（比如关闭）做不到 —— `risk.py` 用 `or` 兜底，0 会被跳过。
> 要关闭必须写负数或改代码。
