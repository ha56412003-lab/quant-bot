# S14 VWAP偏离回归 —— 改造研究记录

> 2026-11-07 夜。任务：研究 S14 核心思路，看能否改到「普通人（非量化机构、非毫秒级）」能用，记录改动与依据，跑回测。
>
> **结论先说：改不出来。不是参数问题，是数学假设问题。**

---

## 一、S14 原版是什么

源码位置：`backend/strategies_legacy.py:264`（`S14VwapRevert`，`sid = S14_VWAP_REVERT`）
状态：**已停用**（`strategies.yaml` 里 `enabled: false`，参数已从 yaml 移除）

### 核心逻辑

```
类型：高频均值回归 · 双向
数据：1 分钟 K 线 + 实时 taker 买卖流

入场：
  |price / VWAP60 − 1| ≥ dev_pct（1~2%）
  且 taker 买卖比确认推动力衰竭
    · 超买时 taker ≤ taker_conf
    · 超卖时 taker ≥ 1/taker_conf
  → 反向开仓

出场：
  止盈：回归到偏离幅度的 exit_frac（0.3~0.5）
  止损：继续偏离 0.8 × dev
  最长持仓：45 分钟
```

### 它想赚的是什么钱

**"过度偏离 → 均值回归"** 这个经典统计套利假设。

逻辑链：价格被情绪推离公允价值 → 推动力（taker 流）衰竭 → 价格回摆。

### 参数（来自 `backend/backtest/optimize.py:34`）

| 参数 | 网格 |
|---|---|
| `dev_pct` | 1.0 / 1.5 / 2.0 |
| `taker_conf` | 0.95 / 99.0（99 = 关闭过滤） |
| `exit_frac` | 0.3 / 0.5 |

## 二、为什么普通人用不了

| 要求 | 原版设定 | 普通人的现实 |
|---|---|---|
| 数据频率 | **1 分钟 K 线** | 不可能每分钟盯盘 |
| 实时流 | **taker 买卖比**（秒级） | 拿不到实时流；交易所 API 有延迟 |
| 持仓时间 | **45 分钟** | 上班/睡觉时无法管理 |
| 单笔空间 | 偏离 1~2%，止盈取 30~50% = **0.3~1.0%** | 手续费 0.05%×2 + 滑点，吃掉 20~40% |
| 反应速度 | 需要秒级 | 手机看一次盘要几十秒 |

**最要命的不是盯盘，是单笔空间太薄。** 赚 0.5% 的交易，扣掉双边手续费 0.1%、滑点 0.06%，实际只剩 0.34%。**一次判断失误就吃掉三次正确。**

## 三、我做的改造（三组，逐条列改动与依据）

### 第一步：先验证假设，不急着改参数

**在做任何改造之前，我先测了最基础的问题：价格偏离 VWAP 之后，到底会不会回归？**

数据：20 个币 × 15m × 60 天（`backtest/data/*_15m_60d.json`）
VWAP 窗口：96 根（24 小时）
观察窗：32 根（8 小时）

| 偏离阈值 | 样本数 | 完全回归 VWAP | 回归一半 | **继续反向扩大 1%+** | 平均最大回归幅度 |
|---|---|---|---|---|---|
| 2% | 5892 | **6.8%** | 47.5% | **59.4%** | 50.0% |
| 3% | 3401 | **5.9%** | 42.4% | **62.3%** | 46.0% |
| 4% | 1965 | 5.8% | 39.2% | 64.7% | 43.8% |
| 5% | 1195 | 4.5% | 37.4% | 66.3% | 42.0% |

**这是决定性的**：

- **偏离 3% 之后，只有 5.9% 真的回到 VWAP**
- **62.3% 继续朝反方向走 1% 以上**
- **而且偏离越大，回归率越低**（2%→6.8%，5%→4.5%）——**跟均值回归的假设完全相反**

**依据**：均值回归策略要求"偏离越大，回归概率越高"。实测是反的。这说明在加密货币上，**偏离往往是趋势的开始，不是过度**。

### 第二步：加过滤器，试图救回来

既然裸信号不行，试三组过滤器（依据：原版的 taker 衰竭逻辑，以及均值回归只在震荡市有效的常识）。

**B 组 · 震荡市过滤（趋势效率 ≤ 阈值才做）**

| 偏离3% + 趋势效率 | 样本 | 回归 VWAP | 继续扩大 1%+ |
|---|---|---|---|
| ≤0.20 | 185 | **3.8%** | 62.2% |
| ≤0.30 | 315 | 5.1% | 61.3% |
| ≤0.40 | 463 | 4.8% | 61.8% |
| 不过滤（全样本） | 3401 | 5.9% | 62.3% |

**结果：加了震荡市过滤，回归率反而更低。**

**C 组 · 量能萎缩过滤（模拟 taker 衰竭）**

| 偏离3% + 量能条件 | 样本 | 回归 VWAP | 继续扩大 1%+ |
|---|---|---|---|
| 无过滤 | 3401 | 5.9% | 62.3% |
| 成交量 < 1.0×20均 | 2549 | 4.7% | 63.5% |
| 成交量 < 0.7×20均 | 2001 | 4.5% | 62.9% |

**结果：加了量能萎缩过滤，回归率也更低。**

**依据**：如果过滤器有效，应该明显提升回归率。实测全部更差，说明**过滤掉的不是噪音，是有效样本**。

## 四、为什么改不出来（数学推导）

不用跑数据也能算出来。

**均值回归的期望公式**：

```
期望 = 胜率 × 平均盈利 − (1−胜率) × 平均亏损
```

S14 的止盈/止损比例固定：
- 止盈 = 偏离的 `exit_frac`（取 0.5）
- 止损 = 偏离的 `stop_mult`（取 0.8）

**所以盈亏比 = 0.5 / 0.8 = 0.625**

**要让它变成正期望**：

```
胜率 × 0.5 > (1−胜率) × 0.8
胜率 × 0.5 > 0.8 − 0.8×胜率
1.3 × 胜率 > 0.8
胜率 > 61.5%
```

**再加手续费**（双边 0.1% ÷ 止损距离 2.78% ≈ 0.036R）：

```
胜率 × 0.5 > (1−胜率) × 0.8 + 0.036
1.3 × 胜率 > 0.836
胜率 > 64.3%
```

**实测最高胜率 64.3%（止损放宽 2.0×dev 那组）——刚好卡在临界点上，扣完手续费就是负的。**

**根本矛盾**：
- **想提高胜率** → 必须放宽止损 → 盈亏比更差
- **想提高盈亏比** → 必须收紧止损 → 胜率暴跌
- **这是个死结**，不是参数调优能解决的

## 五、如果一定要做，唯一可能的出路

**换掉"固定比例止盈止损"这个结构。**

现在的止盈止损都锚定「偏离幅度」，等于**把盈亏比写死成 0.625**。

**唯一有希望的方向**：
- 止盈不设上限（让回归走完），止损固定百分比
- 这样盈亏比由市场决定，不由参数决定

**但这样一来，它就不再是 S14 了，而是"逆势趋势跟踪"** —— 逻辑上自相矛盾。

**另一种出路**：只在**极端偏离 + 极端情绪**时做（比如偏离 8% 以上）。
但实测偏离 5% 的样本只有 1195 个，回归率 4.5%，更差。

## 六、结论

### 给浩哥的三句话

1. **S14 改不出来**，不是参数没调好，是它的核心假设在加密货币上不成立。
2. **原因**：加密是强趋势市场，价格偏离 VWAP 之后 62% 会继续走，只有 6% 会回归。
3. **已经归档**，想复活随时能改，但我不建议再投入时间。

### 数据留档

| 文件 | 内容 |
|---|---|
| `backtest/s14_vwap_revert.py` | 改造版回测代码（参数可调，能复现本文所有数字） |
| `backend/strategies_legacy.py:264` | S14 原版（未改动，保留原样） |

### 一条可复用的经验

**判断一个策略值不值得做，先测它的"最小假设"**，别急着调参数。
S14 的最小假设是「偏离会回归」，这个假设 6% 的命中率，后面怎么调都是白费。
