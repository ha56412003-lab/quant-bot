## ⛔ 第 1 条（生死线）· 必须从全仓 cross 改成逐仓 isolated

### 浩哥原话

> **「现在 OKX 和 Bitget 用的都是全仓 cross，接实盘必须改成逐仓 isolated，
> 否则一个币爆仓会带崩整个账户。作为配置实盘的第一个重要提醒。」**

### 不这么做的后果

全仓（CROSSED）下，账户里**所有仓位共用同一个保证金池**：

```
账户 10,000U，同时开 6 个仓，每个 6x
        ↓
一个币反向暴涨 → 这仓亏光自己保证金还不够
        ↓
亏损直接从「共用池」继续扣 → 池子抽干
        ↓
剩下 5 个本来好好的仓，全部被连环强平
        ↓
一个币的行情，干掉了整个账户
```

逐仓（ISOLATED）下，每个仓的保证金**独立封顶**：

```
每仓分配 X 保证金，最多亏光这 X
        ↓
一个仓爆掉 = 那个仓没了，其余分文不动
        ↓
最坏 = 6 仓全爆 = 亏 6 × X，账户基准资金仍在
```

**这不是优化项，是生死线。** 6 个并发仓位 + 6x 杠杆，全仓模式下只要一个币走极端，
账户一次性归零，连翻身机会都没有。

### 币安跟 OKX/Bitget 不一样：保证金模式是「按币种」设的

这是最容易踩错的地方。

| | OKX | Bitget | **币安** |
|---|---|---|---|
| 保证金模式 | 下单时 `tdMode` | 下单时 `marginMode` | **`POST /fapi/v1/marginType` 单独设，symbol 级** |
| 什么时候设 | 每次下单带 | 每次下单带 | **开仓前先设一次，之后该币一直是这个模式** |

**币安不是「改一个开关全账户生效」，是「每个币都要单独设一遍」。**
6 个仓位 = 6 次设置调用，漏一个就等于那一个币还在全仓。

### 代码现在缺什么（实测，不是推测）

`backend/binance.py` 有这些：`account` / `place_market_order` / `set_leverage` / `exchange_info` / `qty_step`

**没有 `set_margin_type`** —— 也就是说：**现在接币安，默认就是全仓。**

必须补的：

```python
# 新增：设该币种为逐仓
async def set_margin_type(symbol, margin_type="ISOLATED"):
    try:
        return await _signed("POST", FUT, "/fapi/v1/marginType",
                             {"symbol": symbol, "marginType": margin_type})
    except Exception as exc:
        # -4046 = 已经是这个模式，不是错误
        if "-4046" in str(exc):
            return None
        raise   # 别的错误必须抛，不能吞
```

### 三个必须知道的币安错误码

| 码 | 含义 | 怎么处理 |
|---|---|---|
| **-4046** | No need to change margin type | **已经是逐仓了，当成功**（不处理会天天报错） |
| **-4047** | 有挂单不能改保证金模式 | **先撤单，再改** |
| **-4061** | position side 不匹配 | 双向模式下没带 `positionSide` |

### 还有两个账户级开关，必须先在网页端确认

这两个是**全账户统一**的，API 也能查/改，但**切错了会让逐仓白做**：

#### ① 持仓模式 `dualSidePosition`（单向 / 双向）

```
GET  /fapi/v1/positionSide/dual     # 查
POST /fapi/v1/positionSide/dual     # 改
```

- **单向（false）**：一币只有一个方向，下单不带 `positionSide` ← **现在代码就是这个写法**
- **双向（true）**：多空可同时存在，下单**必须**带 `positionSide: LONG|SHORT`

**切换会被拒的情况**：任意一个币有挂单 `-4067`、有持仓 `-4068`。
→ 必须在**空仓空挂单**的状态下切，否则整账户改不了。

**代码现状**：`place_market_order()` **没有 `positionSide` 字段**。
→ 如果你的账户是双向模式，现在的下单代码**会直接报 -4061 全部失败**。

#### ② 多资产模式 `multiAssetsMargin`

```
GET  /fapi/v1/multiAssetsMargin     # 查
POST /fapi/v1/multiAssetsMargin     # 改
```

- **关闭（false，单资产）**：只有 USDT 能当保证金 ← **建议**
- **开启（true）**：BTC/ETH/USDC 等也能自动折抵保证金

**为什么这条重要**：多资产模式下，别的币亏了会自动划转补保证金 ——
**逐仓的「隔离」就被这个机制绕过去了**。开了它，逐仓只能隔离到单币，隔不掉资产间的连环。

**接实盘前必须确认是「单资产模式」。**

### 四笔连锁账（改完字符串也还没完）

#### ① 币安可用余额字段

`/fapi/v2/account` 返回的是 `availableBalance` 和 `totalWalletBalance`。
逐仓下 `availableBalance` 只算「还没被占用」的部分，**这是对的**，
但要确认 `equity()` 读的是这两个字段，不是自己算的。

#### ② 风控参数语义全变，必须重算

| 参数 | 现在（全仓）语义 | 逐仓后语义 |
|---|---|---|
| `max_position_pct_per_coin 32%` | 占总权益 32% | **每仓独立 32%，6 仓 = 192% 名义** |
| `max_gross_leverage 6` | 全账户总杠杆 6x | **每仓各自 6x，账户层面已无意义** |
| `daily_loss_halt_pct 10%` | 参照共用池 | 参照账户基准资金，需重定线 |

#### ③ 强平价算法整个变了

- 全仓：按总权益倒推，仓位越多越容易被拖下水
- 逐仓：只按这一仓的保证金算，跟其他仓无关

`max_hold_hours 16` 和隔夜风险模型都要按逐仓重估。

#### ④ 杠杆分层（Leverage Bracket）

币安每个币的**杠杆上限随名义额递减**（`/fapi/v1/leverageBracket` 可查）。
逐仓后单仓名义额 = 保证金 × 杠杆，会更容易撞到分层边界，
**改完要拉一遍全部持仓币的 bracket，确认 6x 都在允许范围。**

### 验收标准（改完必须实测，不看「应该对了」）

```
[ ] 1. 调 GET /fapi/v1/positionRisk，逐条确认每个持仓 symbol 的
       marginType 字段 == "isolated"            ← 这条最硬，直接查得到
[ ] 2. 交易所网页端「仓位」页，保证金模式列显示「逐仓」
[ ] 3. GET /fapi/v1/multiAssetsMargin 返回 false（单资产模式）
[ ] 4. GET /fapi/v1/positionSide/dual 的返回与下单代码写法一致
[ ] 5. 故意让一个仓接近强平，确认其他仓的保证金和强平价纹丝不动
[ ] 6. availableBalance 与网页端「可用余额」对得上
[ ] 7. 风控参数按逐仓重推后，回测补并发模拟，确认收益没被砍死
```

**7 条全过才能碰真钱。缺一条都不行。**

## 附 · 改逐仓的时候按这个顺序动

```
1. 登录币安网页端，确认三件事：
   ① 持仓模式：单向 or 双向  → 决定下单要不要带 positionSide
   ② 多资产模式：必须关闭
   ③ 当前所有持仓的保证金模式（应该是 CROSSED，待改）

2. 建 API Key，只勾「读取 + 合约交易」，加 IP 白名单，凭据写 E:\Hermes\.env

3. 代码补 set_margin_type()，吞 -4046，抛其他错误

4. 开仓流程里插入：设逐仓 → 设杠杆 → 下单
   （开仓前要保证该币无挂单，否则 -4047）

5. 若账户是双向模式，place_market_order 补 positionSide

6. 风控三参数按逐仓重推 + 拉一遍 leverageBracket 确认 6x 在范围内

7. 测试网（testnet.binancefuture.com）跑满 7 条验收

8. 小资金 500U 真实环境跑一周，每天对账，确认无误

9. 再上正式资金
```

**一步都不能跳。第 8 步那 500U 是学费，比一个仓爆掉便宜得多。**

## 附二 · 币安 vs OKX/Bitget 字段对照（将来要接另两家时看）

| 概念 | 币安 | OKX | Bitget |
|---|---|---|---|
| 逐仓 | `marginType=ISOLATED`（symbol 级，单独接口） | `tdMode="isolated"`（下单带） | `marginMode="isolated"`（下单带） |
| 杠杆 | `POST /fapi/v1/leverage` | `mgnMode` + `lever` | `/api/v2/mix/account/set-leverage` |
| 双向持仓 | `positionSide: LONG/SHORT`（账户级开关） | `posSide` | `holdSide` |
| 单向下单 | 不带 positionSide | 不带 posSide | 不带 holdSide |
| 全仓 | `CROSSED` | `cross` | `crossed` |
| 可用余额 | `availableBalance` | `availBal` | `crossedMaxAvailable`（全仓）／`isolatedMaxAvailable`（逐仓） |
