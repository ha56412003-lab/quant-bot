## ⛔ 第 1 条（最高优先级）· 必须从全仓 cross 改成逐仓 isolated

### 浩哥原话

> **「现在 OKX 和 Bitget 用的都是全仓 cross，接实盘必须改成逐仓 isolated，
> 否则一个币爆仓会带崩整个账户。作为配置实盘的第一个重要提醒。」**

### 不这么做的后果

全仓（cross）下，**账户里所有仓位共用同一个保证金池**：

```
账户 10,000U，同时开 6 个仓，每个 6x 杠杆
        ↓
其中一个币反向暴涨 → 这个仓亏光自己的保证金还不够
        ↓
亏损直接从「共用池」里继续扣 → 池子被抽干
        ↓
剩下 5 个本来好好的仓位，全部被连环强平
        ↓
一个币的行情，干掉了整个账户
```

逐仓（isolated）下，每个仓的保证金**独立封顶**：

```
每个仓分配 X 保证金，最多亏光这 X
        ↓
一个仓爆掉 = 那一个仓没了，其余仓位分文不动
        ↓
最坏情况 = 6 个仓全爆 = 亏 6 × X，账户基准资金仍在
```

**这不是优化项，是生死线。**6 个并发仓位 + 6x 杠杆，全仓模式下只要有一个币走极端行情，
账户就会一次性归零，连翻身的机会都没有。

### 代码里现在有三处写死了 cross

| 文件 | 行 | 现在 | 要改成 |
|---|---|---|---|
| `backend/exchanges.py` | `:98` | `"tdMode": "cross"`（OKX 下单） | `"isolated"` |
| `backend/exchanges.py` | `:110` | `"mgnMode": "cross"`（OKX 设杠杆） | `"isolated"` |
| `backend/exchanges.py` | `:180` | `"marginMode": "crossed"`（Bitget 下单） | `"isolated"` |

### 但改这三个字符串还不够 —— 逐仓有四笔连锁账

浩哥，下面四件事我列出来，是想让你知道**这不是点一下开关就完事的**。
每一条不改，逐仓就是白改，甚至比全仓更糟。

#### ① OKX 要先确认账户是「单向持仓」还是「双向持仓」

- **单向模式**：下单不用带 `posSide`，现有代码就是按单向写的
- **双向模式**：逐仓下单**必须**带 `posSide: "long"` / `"short"`，代码现在完全没这个字段

改之前必须先登录 OKX 看账户模式。**如果是双向，光改 `tdMode` 会直接下单失败。**

#### ② Bitget 的可用余额读错字段，风控会算错

`exchanges.py:202` 现在读的是：

```python
avail = float(row.get("crossedMaxAvailable") or row.get("available") or 0)
```

`crossedMaxAvailable` 是**全仓可用**。逐仓之后这个数会失真，
要用 `isolatedMaxAvailable` 或直接 `available`。

**后果**：风控以为可用余额还很充裕，实际上已经被逐仓各占各的，
会开出超过实际承受能力的仓位。

#### ③ 风控参数语义全变，必须重算

| 参数 | 现在（全仓）语义 | 逐仓后语义 |
|---|---|---|
| `max_position_pct_per_coin 32%` | 占总权益 32% | 每仓独立 32%，6 仓 = 192% 名义 |
| `max_gross_leverage 6` | 全账户总杠杆 6x | 每仓各自 6x，账户层面已无意义 |
| `daily_loss_halt_pct 10%` | 参照共用池 | 参照账户基准资金，需重新定线 |

**这三个数在逐仓下不能直接沿用，要重新推一遍。**

#### ④ 强平价算法整个变了

- 全仓：强平价按**总权益**倒推，仓位越多越容易被拖下水
- 逐仓：强平价只按**这一仓的保证金**算，跟其他仓无关

**24 小时持仓上限（`max_hold_hours 16`）和隔夜风险模型都要按逐仓重估。**

### 验收标准（改完必须实测，不看"应该对了"）

```
[ ] 1. 在测试网（OKX demo / Bitget 模拟）各开一个仓
[ ] 2. 查交易所后台，确认该仓的「保证金模式」显示为 逐仓 / Isolated
[ ] 3. 故意让这一仓接近强平，确认其他仓位的保证金和强平价纹丝不动
[ ] 4. `bitget_equity()` / `okx_equity()` 返回的 available 与交易所显示一致
[ ] 5. 风控参数按逐仓重推后，用回测补一轮并发模拟验证收益没被砍死
```

**5 条全过才能碰真钱。缺一条都不行。**

## 第 2 条 · 下单类型写死 market，没有滑点保护

`exchanges.py:99` / `:182`：`"ordType": "market"` 硬编码。

市价单在极端行情下会吃到很差的价。逐仓本身没问题，但要评估：
**流动性差的币，市价单滑点可能直接吃掉 1R 的三分之一。**

待定：要不要加限价单 + 滑点上限，或者对低流动性币种单独降杠杆。

## 第 3 条 · OKX 拒单被当成成功（已知老坑）

`data[0]["sCode"]` 没检查。OKX 返回 `code: "0"` 但 `sCode` 非 0 时，实际是**拒单**，
程序会以为下单成功 → 账实不符 → 后面所有对账全乱。

（币安、Bitget 已有检查，只有 OKX 这条漏了。）
