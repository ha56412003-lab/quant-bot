## 系统怎么运转（先看这个）

### 一句话版

> **每天筛 200 个 → 实时盯 40 个 → 每 15 分钟判一次能不能开 → 开了之后每 0.5 秒盯着要不要平。**

### 三层节奏（这是理解全系统的钥匙）

| 层 | 多久跑一次 | 干什么 | 代码 |
|---|---|---|---|
| **候选池** | 每天 03:00 | 从 500+ 个合约里选 200 个有波动潜力的 | `backend/pool.py` |
| **监控池** | **60 秒** | 给 50 个币算「有没有资格被交易」 | `backend/quality.py` |
| **策略扫描** | **15 分钟** | 判「现在能不能开仓」，能就下单 | `backend/strategies.py` |
| **持仓管理** | **0.5 秒** | 盯「要不要平仓」 | `backend/engine.py` |

**为什么进场慢（15 分钟）、出场快（0.5 秒）？**

因为这个策略的所有进场条件（CE 转向、HA 形态、BBW 分位、偏离均线）**都依赖 15 分钟 K 线的收盘价**。
K 线没走完时指标会来回闪，用未收盘的 K 线判信号等于自欺欺人。
把周期改成 5 分钟回测 2,504 笔 **−359R**（灾难），所以维持 15 分钟。

而仓位一旦开了，风险是**实时**的 —— 价格随时可能插针，所以出场检查跑在 0.5 秒。

### 关键设计原则

| 原则 | 为什么 |
|---|---|
| **进场判据必须用收盘价** | 未收盘 K 线的指标会闪，造成假信号 |
| **出场不依赖监控池** | 仓位一旦开了就是独立责任，掉出池也照常保护（出场遍历 `positions` 表） |
| **多空完全对称** | 代码是镜像的（已用镜像测试证明差 2.8R / 1.1R），空头赚得少只能是行情原因，不能是策略原因 |
| **单币独立风险** | 每笔按 R 计算，1R = 本金的 1.5%，不因仓位多少改变 |
| **不做马丁、不加仓、不摊平** | 一个仓位从开到平，只有「平一半」这一个中间动作 |

## 进场逻辑：一个币怎么被选出来并买入

### 第 1 关 · 候选池（每天一次）

```python
# strategies.yaml → pools.candidate
size: 200              # 取前 200 个
min_amp_pct: 10.0      # 30 天振幅 ≥ 10%
max_amp_pct: 300.0     # 且 ≤ 300%（排除刚上线的妖币）
vol_days: 30
```

**目的**：把 500+ 个合约缩到 200 个「有波动、有流动性」的池子。

### 第 2 关 · 监控池（每 60 秒）

两道资格闸，全过才进池：

| 闸 | 条件 | 参数 | 代码 |
|---|---|---|---|
| ① 成交额 | 24h ≥ **500 万 U** | `min_quote_vol: 5000000` | `quality.py` |
| ② 插针 | 单根振幅 ÷ ATR ≤ **8.0** | `max_spike: 8.0` | `quality.py` |

**2026-11-10 定档删掉的两道闸**：③ 止损距离（原进 0.50% / 出 0.30%）、④ 白名单直通。
止损距离那道把主流大币全挡在池外（BTC 0.316% / ETH 0.490% / BNB 0.352% / DOGE 0.403%）——
「止损太窄」不是进不进池的问题，是止损取法的问题，改由第 3 关的**止损两档**解决。
趋势效率（EFF）则早已从池子闸挪到开仓第 ⑥ 道（`eff_min_signal`），池子层 `eff_min: 0` = 关闭。

**EFF（趋势效率）是什么，为什么不用涨跌幅**（现在用作开仓第 ⑥ 道闸）：

```
amp = (窗口内最高价 - 窗口内最低价) / 窗口内最低价
eff = |末收盘 / 首收盘 - 1| / amp
```

`eff = 1.0` 表示价格从最低点一路涨到最高点（完美单边）；
`eff = 0.1` 表示区间很大但价格来回震荡（宽幅震荡）。

**判据**（禁止用 24h 涨跌幅，那个数字区分不出「单边」和「震荡」）：

```
eff >= 0.55  单边趋势
eff <= 0.30  宽幅震荡 → 不进池
中间         半趋势
```

**池子是有限的（40 个位置），按 24h 成交额排。**
热门币多了，小币就被挤出去（这叫「池满未入选」，不是质量不行）。

**进池有保护**：进池后 300 秒内不会被踢（`min_dwell_sec`，11-10 从 900 收到 300 —— 池边界第 40/41 名只差 7%，15 分钟会让掉队币白占坑）。

### 第 3 关 · 策略信号（每 15 分钟）

**只在监控池内的币上跑**，七道闸，顺序就是代码顺序（`strategies.py::evaluate`）：

| 闸 | 条件 | 参数（B 档） | 砍掉多少 |
|---|---|---|---|
| ① CE 方向翻转 | Chandelier Exit 方向由 −1 变 +1（做多）或反之 | `ce_len: 1` / `ce_mult: 1.5` | — |
| ② HA 方向 K 线 | Heikin-Ashi 出现同向形态，且收在 ZLSMA50 同侧 | `use_ha: true` / `zlsma_len: 50` | ~24% |
| ②b 关键 K 线 | **原始 K 线**（不是 HA）实体 > 0.7×ATR(20)，且 (收−低)/(高−低) > 0.66、(收−开)/(高−低) > 0.5 | `key_bar: true` / `key_mult: 0.7` | **约 90%（最窄的一道）** |
| ③ BBW 分位 | 布林带宽度分位 > 70%（波动正在放大） | `bbw_pct_min: 70.0` | ~81% |
| ④ 偏离均线 | `|当前价 − ZLSMA50| / ZLSMA50 × 100` ≥ max(`min_dev_pct`, `dev_atr_mult × ATR(20)/价 × 100`) | `min_dev_pct: 0` / `dev_atr_mult: 1.0` | 少量 |
| ⑤ 止损距离 | 三条取近后的止损距离 ≤ 5% | `max_risk_pct: 5.0` | 少量 |
| ⑥ 趋势效率 | 近 48 根 15m 的 EFF ≥ 0.30（趋势效率，**不用 24h 涨跌幅**） | `eff_min_signal: 0.30` / `eff_win_signal: 48` | ~29% |

七道闸全过的概率约 **0.6%**（12 万根 K 线 → 44 笔），所以「今天没开仓」绝大多数时候是真没机会，不是程序坏了。具体卡在哪一道，看面板的**「七道闸」**页签（逐币显示每一道通过/失败，以及真实门槛值）。

**止损价怎么定：分两档**（`dual_stop_min_pct: 0.5`，`swing_lookback: 8`）

```
先按三条并列取近算一遍（多头取三者最高、空头取最低）：
  ① 左侧 8 根摆动：做多取前 8 根最低点 / 做空取前 8 根最高点（进场那刻定死，之后不动）
  ② CE 通道：Chandelier Exit 的 long_stop / short_stop
  ③ 关键 K 线极值：进场那根关键 K 线的 low（多）/ high（空）

然后看这一遍算出来的距离（★ 不看止损来自哪一条，只看距离）：
  ≥ 0.50%  → 就用它（第一档，三条取近）
  < 0.50%  → 改用 ② CE 通道（第二档，①②③ 全部不算）
```

> 口径要点（2026-11-10 修正）：判定条是「**三条取近后的距离 < 0.50%**」，
> **不管这个止损来自摆动、CE 还是关键 K 线**。早期实现只对「来源=关键 K 线」的单生效，
> 比回测母本（`backtest/exit_speed_test.py` 的 `dual_stop_min_pct`）严，已改回不限来源。

为什么要有第二档：主流大币的关键 K 线离收盘太近，止损只有 0.3~0.5%，1R 太小，
一点噪音就被打穿（实测 BTC 单币胜率只有 30%）。改用 CE 通道后止损撑到 1.1~1.4%，
同一批币胜率 51.6% → 54.8%、净 R 多 14.84R。

实测（`scripts/verify_dual_stop.py` 逐根回放 BTC+DOGE 60 天）：
止损 <0.50% 的单 **5 → 1（−80%）**，中位 0.68% → **0.79%**，最小 0.22% → **0.48%**。
残留那 1 笔是 CE 通道本身就只有 0.48% —— 它是最后一道防线，与回测母本同口径。

**「K 线幅度越大越靠谱」是错的**：关键 K 线按幅度分桶后，1.8~2.5×ATR(20) 那档只有 30.8% 胜率。它的作用是「排掉没力气的 K 线」，不是「挑最猛的」。

## 出场逻辑：一个仓位怎么被平掉

**跑在 `position_loop`，每 0.5 秒一轮**，遍历 `positions` 表里所有开着的仓位。同一根 15m K 线的判定结果会缓存（`_bar_pack`），不会 0.5 秒重算一遍、也不会多拉一次 K 线。

> 出场检查**完全不看监控池**。仓位就算掉出池了，四条出场一条不少。

### 四条出场（按检查顺序）

| # | 触发条件 | 动作 | 参数 | 谁判 |
|---|---|---|---|---|
| 0 | 价格穿硬止损 | **全平** | 开仓那刻算好的止损价 | `engine.py`（优先级最高，先判） |
| 1 | 浮盈到 **1.2R** | **平一半** | `half_at_r: 1.2` | `_half_take_profit` |
| 2 | 已平半 且 浮盈到 **2.0R** | **剩余全平**（兜底） | `full_at_r: 2.0` | `_full_target` |
| 3 | 已平半 且 HA 反向 **且** HA 收穿 ZLSMA50 **且** 那根原始 K 线本身是反向关键 K 线 | **剩余全平**（右侧止盈） | `right_exit: true` / `right_exit_strict: true` | `_right_exit` |

**为什么是这个顺序**

1.2R 平半是「锁定不亏」的转折点 —— 先落袋一半，剩下的仓位才敢让它跑。2.0R 兜底是为了防止「平半后一直不穿均线」把利润耗回去。右侧止盈负责吃趋势尾巴，但它**必须等平半之后**才允许触发（测试 `E7`：没平半时不许抢跑）。

### 2026-11-10 B 档删掉的四条（方法和配置一起删，不是关开关）

| 删掉 | 为什么 |
|---|---|
| **16h 时间止损** | 把「慢性子但最终赚钱」那批砍在时间线上；改由 2.0R 兜底 |
| **快速失败**（4h 内峰顶没到 0.5R 就平） | 实跑 11~12 笔 −328~−440U，全是白送 |
| **镜像出场**（CE 翻转 + HA 反向 + BBW 分位≥70） | 与右侧止盈后两条完全重叠，且会抢在右侧止盈前掐单：留着 60.0% / 1.67 / +23.48R / 4.25h，删掉 61.1% / 1.61 / +23.11R / 5.72h —— 差 0.37R，但删掉后持仓长 1.47h（右侧止盈给它空间跑） |
| **移动止盈 / 平半后再赚 N 个 R 全平**（`trail_arm` / `trail_dd` / `half_tp_r`） | 与 2.0R 兜底抢同一个出口，留着只会把大肉提前切掉 |

| BBW 门槛放 60 / 50 / 关掉 | 胜率立刻从 55% 掉到 50%，盈亏比 1.0，净利归零（只删这一道 −44.30R） |
| 镜像出场 | 见上 |
| 5 分钟周期 | 11 种配置全负，最好 −11.4R 且只剩 1.13 单/天 |

### 方案 Z（当前生效）

```
risk_per_trade_pct      : 1.5%      → 1R ≈ 150 U（1 万本金）
max_concurrent_coins    : 8         → 最多持 8 个币
max_same_side           : 6         → 同向最多 6 个
```

## 2026-11-11 · 三条改动（浩哥拍板）

> 第三条「同一根 K 线同向最多 2 笔」是 17:00 定的，配套把择优排序从 strength 降序改成升序。

### ⑦ 同一信号时点同向最多 2 笔（`max_same_bar_side: 2`）

- **在哪**：`backend/engine.py` 的 `scan_loop`，`risk.allow_entry` 之后、下单之前（跨币限流，不在七道闸表里）
- **为什么**：池内所有币在同一根 15m K 线上会一起算出同向信号 —— 那是 1 个机会 × N 个标的，不是 N 个独立机会。
  11-10 23:45:22 因此一秒开了 6 个空，V 型反转全灭，已平 7 笔 −1,089.71U。
- **配套**：择优排序 `signals.sort` 从 `strength` **降序**改成 **升序**（`strength = |收盘−ZLSMA50|/ATR`，
  降序 = 专挑追得最狠的先开，限笔时把好信号挤掉）。只改限笔数不改排序，结论会反转（实测 +49.78R → +44.33R）。
- **实测（K 线到 11-11，281 笔）**：**4.68 单/天 / 54.1% / 1.33 / +45.93R / −9.70R / 4.35h**；未限笔是 5.03 / 55.3% / +55.02R / −10.03R —— 用 −7% 单量换了回撤收窄和「一秒开 6 单」的灾难免疫
- **验证**：`scripts/verify_same_bar_cap.py`（22 项，已挂总检 ④c 门）
- **已否决**：「同向并发限笔」（任意时刻同向持仓 ≤N）全线更差（−2.41 ~ −23.64R），因为它拦的是不同时点的正常信号


### ⑤ 进场第⑤道闸加「止损距离下限 0.60%」
`strategies.yaml → S15_CE_ZLSMA.params.min_stop_dist_pct = 0.60`
（`backend/strategies.py` evaluate() 第⑤道闸，与「止损 ≤5%」同一个判定块，一上一下）

**为什么**：手续费按名义仓位收（0.05%×2），止损越窄，手续费占 1R 的比例越大。
40 币 60 天按入场止损距离分桶：

### ① 保本移损 1.5R
`params.be_at_r = 1.5` + `positions.be_on` 列（`backend/db.py` 迁移）

**怎么实现（重要）**：**不改 `stop_price`**。
`stop_price` 是全系统算 R 的分母（`abs(entry-stop_price)`），一旦改成入场价，
`_refresh_peak` / `_half_take_profit` / `_full_target` / `_right_exit` 全部除零。
所以：峰顶到 1.5R → `check_exit` 置 `be_on=1` 并落库 →
`engine._hard_stop_reason()` 判止损时把触发价换成 `entry_price`，reason 记「保本止损」。

**实测代价（如实写）**：单加 1.5R 保本 = 5.60 / 55.1% / 1.31 / **+52.54R**（比不加多 +0.33R）。
和 ⑤ 叠加后：⑤ 单独 +56.68R → 叠加后 **+55.02R（−1.66R）**，但回撤 −10.25 → −10.03R。
即「保本换回撤」，不是白赚 —— 它砍掉 18 笔本来能到 2R 的大赢（合计 −14.02R），
救回 38 笔原本亏 1R 的单（+13.98R）。

**第一版有个真 BUG（已修，记录在此）**：`update_position` 有字段白名单
`_POSITION_WRITABLE`，里面没有 `be_on` → 直接抛 `ValueError` →
被 `log.debug` 吞掉 → **yaml 有键、代码看着对、实际从来没生效**。
修法：白名单加 `be_on`；落库失败从 `debug` 升到 `warning`。
教训：**写库失败不能用 debug 级别吞**；**yaml 有键 ≠ 规则已实现**。
新增 `scripts/verify_breakeven.py`（16 项，真调 `check_exit`）并挂进第六道门。

### 两个值得记住的教训

**① 一个接口 401 不该等于一个页面白屏。**

`ConfigPage.jsx:111` 用了裸 `fetch`（不带 `x-api-token`）→ 后端 401 →
401 的响应体 `{detail:"..."}` 被当成数据 → `if (!info)` 拦不住（错误响应也是对象）→
`info.exchange.toUpperCase()` 读到 undefined → React 崩 → 整页白屏。

**规矩**：前端所有请求必须走 `api.get` / `api.post`，禁止裸 `fetch`
（`rg "fetch\(" frontend-v2/src` 结果应该只有 `api.js` 里那几处）。

**② 手动全平 ≠ 日目标达成。**

旧代码平完仓调 `daily_target.mark_done("手动一键全平")` → `risk.py:134` 直接锁死当天开仓。
现在两者语义分开：

```
手动一键全平 = 清掉仓位重新来（风险动作）
日目标 done  = 当日盈利 ≥ target，落袋收工（收益动作）
```

### 派生的运维约定

- **改参数是「本地改 + 服务器就地改同一个值」**，不是整份覆盖 yaml；服务器改前 `cp -a` 备份。
- **改 yaml 不用重启**：`config.pools()` / `load_strategies()` 每次调用重读文件，
  `quality.loop()` 每 60 秒调一次 `configure()` → **最坏等 2 分钟生效**。
- **换前端只需换 `dist`**：后端 `StaticFiles` 直接读磁盘，不用重启。

## 这套策略的弱点（诚实说明）

### 1. 没有闸能在 12 分钟内分辨真假突破

11-09 当天 4 笔大亏 −627 U（占当日 83%）全部在 **0.2 / 1.5 / 1.2 / 0.3 小时**内硬止损。
原快速失败闸要 4 小时才生效，根本来不及 —— **B 档已把它整条删除**，现在这条弱点没有任何闸能挡，属于已知风险。

当天 13 笔的 `dev` 全部 > 0.5%（最低 0.78%）→ 偏离闸一笔没挡住。现在偏离门槛改成自适应 1.0×ATR(20)（通常 0.4%~0.8%），比固定 0.5% 更贴当根波动，但对「瞬间插针式突破」依然无效。

**这是策略结构的固有弱点，不是参数能解决的。**

### 2. 利润高度依赖少数大赢单

任何「更早出场」的尝试都会砍到右尾。回测里试过六条路，全部让净 R 或回撤恶化。

### 3. 池子容量有限会漏掉机会

40 个位置按成交额排。热门币多了，质量不错但成交额低的币会被挤出去

**接实盘前必须先在测试网跑通验收 5 条**（见实盘检查清单）。

### 5. 交易所侧没有止损单

所有止损都在本地判断。**服务挂了 = 裸仓。**
这是已知问题，接实盘前必须解决。

## 可靠性：2026-11-10 修的一个真 BUG

**现象**：`logs/server.log` 里每天 08:16 都有一条 `ERROR engine: position loop tick failed`，
紧跟看门狗「循环已退出，自动重启」—— 也就是说 **每天早盘那 20~30 秒，止损/止盈是停摆的**。

**根因**：08:16 是质量/因子日刷新，长事务占着 sqlite 写锁超过 `busy_timeout`(8s)。
心跳写 `db.set_meta("last_manage_ts_ms", ...)` 抛 `database is locked`，
异常一路冒出 tick 的 try 块 → **整个 0.5 秒循环退出**。

**修法**（两处，都不动交易逻辑）：

1. 心跳改走 `db.heartbeat_meta()` —— 独立连接 + 0.25 秒超时，写不进去立刻放弃、打 warning、循环继续。
   心跳只是给看门狗看的存活标记，绝不能拖住真正管钱的循环。
2. `db.set_meta()` 自身加重试 3 次（0.3/0.6/0.9 秒退避），钱相关的写不再一次失败就丢。

**验证**（`scripts/verify_heartbeat_resilience.py`，真实持锁 12 秒）：

| | 修复前 | 修复后 |
|---|---|---|
| 循环是否退出 | 退出，看门狗重启 | **不退出** |
| 心跳多久恢复 | 16~19 秒（一直卡在写库上） | **0.0 秒** |
