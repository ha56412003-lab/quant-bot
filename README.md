**一套自托管的加密货币永续合约量化交易系统。**

从全市场 500+ 个合约里自动筛出可交易的，用趋势跟踪策略决定何时进出，

## 系统怎么运转（先看这个）

### 一句话版

> **每天筛 200 个 → 实时盯 40 个 → 每 15 分钟判一次能不能开 → 开了之后每 0.5 秒盯着要不要平。**

### 三层节奏（这是理解全系统的钥匙）

| 层 | 多久跑一次 | 干什么 | 代码 |
|---|---|---|---|
| **候选池** | 每天 03:00 | 从 500+ 个合约里选 200 个有波动潜力的 | `backend/pool.py` |
| **监控池** | **60 秒** | 给 40 个币算「有没有资格被交易」 | `backend/quality.py` |
| **策略扫描** | **15 分钟** | 判「现在能不能开仓」，能就下单 | `backend/strategies.py` |
| **持仓管理** | **0.5 秒** | 盯「要不要平仓」 | `backend/engine.py` |

**为什么进场慢（15 分钟）、出场快（0.5 秒）？**

因为这个策略的所有进场条件（CE 转向、HA 形态、BBW 分位、偏离均线）**都依赖 15 分钟 K 线的收盘价**。
K 线没走完时指标会来回闪，用未收盘的 K 线判信号等于自欺欺人。
把周期改成 5 分钟回测 2,504 笔 **−359R**（灾难），所以维持 15 分钟。

而仓位一旦开了，风险是**实时**的 —— 价格随时可能插针，所以出场检查跑在 0.5 秒。

```
    ╚═══════════════════════════════════════════════════════╝
```

### 关键设计原则

| 原则 | 为什么 |
|---|---|
| **进场判据必须用收盘价** | 未收盘 K 线的指标会闪，造成假信号 |
| **出场不依赖监控池** | 仓位一旦开了就是独立责任，掉出池也照常保护（出场遍历 `positions` 表） |
| **多空完全对称** | 代码是镜像的（已用镜像测试证明差 2.8R / 1.1R），空头赚得少只能是行情原因，不能是策略原因 |
| **单币独立风险** | 每笔按 R 计算，1R = 本金的 1.5%，不因仓位多少改变 |
| **不做马丁、不加仓、不摊平** | 一个仓位从开到平，只有「平一半」这一个中间动作 |

## 进场逻辑：一个币怎么被选出来并买入

### 第 1 关 · 候选池（每天一次）

```python
# strategies.yaml → pools.candidate
size: 200              # 取前 200 个
min_amp_pct: 10.0      # 30 天振幅 ≥ 10%
max_amp_pct: 300.0     # 且 ≤ 300%（排除刚上线的妖币）
vol_days: 30
```

**目的**：把 500+ 个合约缩到 200 个「有波动、有流动性」的池子。

### 第 2 关 · 监控池（每 60 秒）

四道资格闸，全过才进池：

| 闸 | 条件 | 参数 | 代码 |
|---|---|---|---|
| ① 止损距离 | 前 20 根阶段低/高点距离 ≥ **1.0%** | `stop_min_pct: 1.0` | `quality.py` |
| ② 趋势效率 EFF | ≥ **0.30**（96 根 15m = 24 小时窗口） | `eff_min: 0.3` | `quality.py::_eff` |
| ③ 成交额 | 24h ≥ **500 万 U** | `min_quote_vol: 5000000` | `quality.py` |
| ④ 插针 | 96 小时内最大插针 ≤ **8.0%** | `max_spike: 8.0` | `quality.py` |

**EFF（趋势效率）是什么，为什么不用涨跌幅：**

```
amp = (窗口内最高价 - 窗口内最低价) / 窗口内最低价
eff = |末收盘 / 首收盘 - 1| / amp
```

`eff = 1.0` 表示价格从最低点一路涨到最高点（完美单边）；
`eff = 0.1` 表示区间很大但价格来回震荡（宽幅震荡）。

**判据**（禁止用 24h 涨跌幅，那个数字区分不出「单边」和「震荡」）：

```
eff >= 0.55  单边趋势
eff <= 0.30  宽幅震荡 → 不进池
中间         半趋势
```

**池子是有限的（40 个位置），按 24h 成交额排。**
热门币多了，小币就被挤出去（这叫「池满未入选」，不是质量不行）。

**进池有保护**：进池后 900 秒内不会被踢（`min_dwell_sec`），防止指标抖动导致反复进出。
清退比进池宽松（`eff_exit: 0.25` vs `eff_min: 0.30`），也是防抖。

### 第 3 关 · 策略信号（每 15 分钟）

**只在监控池内的币上跑**，七道闸，顺序就是代码顺序（`strategies.py::evaluate`）：

| 闸 | 条件 | 参数（B 档） | 砍掉多少 |
|---|---|---|---|
| ① CE 方向翻转 | Chandelier Exit 方向由 −1 变 +1（做多）或反之 | `ce_len: 1` / `ce_mult: 1.5` | — |
| ② HA 方向 K 线 | Heikin-Ashi 出现同向形态，且收在 ZLSMA50 同侧 | `use_ha: true` / `zlsma_len: 50` | ~24% |
| ②b 关键 K 线 | **原始 K 线**（不是 HA）实体 > 0.7×ATR(20)，且 (收−低)/(高−低) > 0.66、(收−开)/(高−低) > 0.5 | `key_bar: true` / `key_mult: 0.7` | **约 90%（最窄的一道）** |
| ③ BBW 分位 | 布林带宽度分位 > 70%（波动正在放大） | `bbw_pct_min: 70.0` | ~81% |
| ④ 偏离均线 | `|当前价 − ZLSMA50| / ZLSMA50 × 100` ≥ max(`min_dev_pct`, `dev_atr_mult × ATR(20)/价 × 100`) | `min_dev_pct: 0` / `dev_atr_mult: 1.0` | 少量 |
| ⑤ 止损距离 | 三条取近后的止损距离 ≤ 5% | `max_risk_pct: 5.0` | 少量 |
| ⑥ 趋势效率 | 近 48 根 15m 的 EFF ≥ 0.30（趋势效率，**不用 24h 涨跌幅**） | `eff_min_signal: 0.30` / `eff_win_signal: 48` | ~29% |

七道闸全过的概率约 **0.6%**（12 万根 K 线 → 44 笔），所以「今天没开仓」绝大多数时候是真没机会，不是程序坏了。具体卡在哪一道，看面板的**「七道闸」**页签（逐币显示每一道通过/失败，以及真实门槛值）。

**止损价怎么定：三条并列取近**（`swing_lookback: 8`）

```
① 左侧 8 根摆动：做多取前 8 根最低点 / 做空取前 8 根最高点（进场那刻定死，之后不动）
② CE 通道：Chandelier Exit 的 long_stop / short_stop
③ 关键 K 线极值：进场那根关键 K 线的 low（多）/ high（空）
→ 多头取三者最高、空头取三者最低（尽量贴着价格，止损越近仓位越大）
```

实测：99% 的单子止损来自关键 K 线那条，中位止损距离 1.30%、区间 0.50%~4.87%。

**「K 线幅度越大越靠谱」是错的**：关键 K 线按幅度分桶后，1.8~2.5×ATR(20) 那档只有 30.8% 胜率。它的作用是「排掉没力气的 K 线」，不是「挑最猛的」。

### 第 4 关 · 风控闸门（九道，见下一节）

### 第 5 关 · 下单

```
数量 = (本金 × 1.5%) / |开仓价 − 止损价|
```

市价单，逐仓 isolated，杠杆 6x（逐仓由代码自动设置，只对要开的币设）。

## 出场逻辑：一个仓位怎么被平掉

**跑在 `position_loop`，每 0.5 秒一轮**，遍历 `positions` 表里所有开着的仓位。同一根 15m K 线的判定结果会缓存（`_bar_pack`），不会 0.5 秒重算一遍、也不会多拉一次 K 线。

> 出场检查**完全不看监控池**。仓位就算掉出池了，四条出场一条不少。

### 四条出场（按检查顺序）

| # | 触发条件 | 动作 | 参数 | 谁判 |
|---|---|---|---|---|
| 0 | 价格穿硬止损 | **全平** | 开仓那刻算好的止损价 | `engine.py`（优先级最高，先判） |
| 1 | 浮盈到 **1.2R** | **平一半** | `half_at_r: 1.2` | `_half_take_profit` |
| 2 | 已平半 且 浮盈到 **2.0R** | **剩余全平**（兜底） | `full_at_r: 2.0` | `_full_target` |
| 3 | 已平半 且 HA 反向 **且** HA 收穿 ZLSMA50 **且** 那根原始 K 线本身是反向关键 K 线 | **剩余全平**（右侧止盈） | `right_exit: true` / `right_exit_strict: true` | `_right_exit` |

**为什么是这个顺序**

1.2R 平半是「锁定不亏」的转折点 —— 先落袋一半，剩下的仓位才敢让它跑。2.0R 兜底是为了防止「平半后一直不穿均线」把利润耗回去。右侧止盈负责吃趋势尾巴，但它**必须等平半之后**才允许触发（测试 `E7`：没平半时不许抢跑）。

### 2026-11-10 B 档删掉的四条（方法和配置一起删，不是关开关）

| 删掉 | 为什么 |
|---|---|
| **16h 时间止损** | 把「慢性子但最终赚钱」那批砍在时间线上；改由 2.0R 兜底 |
| **快速失败**（4h 内峰顶没到 0.5R 就平） | 实跑 11~12 笔 −328~−440U，全是白送 |
| **镜像出场**（CE 翻转 + HA 反向 + BBW 分位≥70） | 与右侧止盈后两条完全重叠，且会抢在右侧止盈前掐单：留着 60.0% / 1.67 / +23.48R / 4.25h，删掉 61.1% / 1.61 / +23.11R / 5.72h —— 差 0.37R，但删掉后持仓长 1.47h（右侧止盈给它空间跑） |
| **移动止盈 / 平半后再赚 N 个 R 全平**（`trail_arm` / `trail_dd` / `half_tp_r`） | 与 2.0R 兜底抢同一个出口，留着只会把大肉提前切掉 |

### 出场侧已经试过、全部否掉的方向（别再试）

| 方向 | 结果 |
|---|---|
| 收紧止损（3% 上限） | >3% 那批 22 笔 / 59.1% / +0.390R，**是最赚钱的一档**，上限放到 5% |
| 加宽止损（缓冲/取远） | 四档全劣，取远直接腰斩 |
| CE 倍数 2.5 / 3.0 | 非单调，1.5 最优（作者原设计 2.0） |
| BBW 门槛放 60 / 50 / 关掉 | 胜率立刻从 55% 掉到 50%，盈亏比 1.0，净利归零（只删这一道 −44.30R） |
| 镜像出场 | 见上 |
| 5 分钟周期 | 11 种配置全负，最好 −11.4R 且只剩 1.13 单/天 |

## 风控：下多少、能开几个

### 九道进场闸（`risk.allow_entry`）

| # | 闸 | 参数 |
|---|---|---|
| 1 | 日熔断（当日亏损 ≥ 10%） | `daily_loss_halt_pct: 10.0` |
| 2 | 日目标（当日盈利达标后停开新仓） | `daily_target.target_usd: 500` |
| 3 | 事件静默（重大事件前后 30 分钟） | `event_quiet_minutes: 30` |
| 4 | 并发币种数 | `max_concurrent_coins: 8` |
| 5 | 同向持仓数 | `max_same_side: 6` |
| 6 | 总杠杆 | `max_gross_leverage: 6` |
| 7 | 单币名义上限 | `max_position_pct_per_coin: 32.0%` |
| 8 | 单笔风险比例 | `risk_per_trade_pct: 1.5%` |
| 9 | 同币冷却 | — |

### 方案 Z（当前生效）

```
risk_per_trade_pct      : 1.5%      → 1R ≈ 150 U（1 万本金）
max_concurrent_coins    : 8         → 最多持 8 个币
max_same_side           : 6         → 同向最多 6 个
max_gross_leverage      : 6x        → 总敞口上限 6 倍
max_position_pct_per_coin: 32%      → 单币名义上限
daily_loss_halt_pct     : 10%       → 日亏 10% 全停
daily_target            : 500 U     → 日赚 500 停开新仓（可手动重置）
```

**60 天回测**：+5,283 U / 回撤 2,947 U / 最低净值 7,058 U。

### 三个容易踩的坑（已写进文档）

1. **不改单币上限，风险比例白改** —— 单币名义被 32% 截断时，1.5% 的实际含义就变了
2. **回测必须补并发模拟** —— 单币独立跑出来的收益是假的（并发 3 只吃 18.75R，并发 6 吃 35.20R）
3. **接实盘第一件事是把 cross 改 isolated** —— 现在 OKX / Bitget 写死全仓

## 回测成绩

### B 档（40 币 / 60 天 / 2026-11-10 定稿）

| 指标 | 实测 |
|---|---:|
| 单量 | **4.65 单/天**（279 笔） |
| 胜率 | **54.8%** |
| 盈亏比 | **1.36** |
| 净值 | **+48.95R**（+0.1755R/笔） |
| 回撤 | **−13.41R** |
| 持单时间 | 均 **3.98h** / 中位 2.25h |

换钱（1R = 本金 1.5% = 150U）：+48.95R ≈ +7,343U；复利落到 20,000U 上下，收益/回撤 ≈ 3.6。

出场归因：硬止损 52.9% −108.8R / 右侧止盈 18.5% +34.5R / 平半 15.4% +66.9R / 2.0R 全平 13.2% +48.0R。

### 版本对照（同一批 40 币）

| 方案 | 单/天 | 胜率 | 盈亏比 | 净 R | 回撤 | 均持 |
|---|---:|---:|---:|---:|---:|---:|
| 原方案（key 1.0 / cap 3%） | 2.68 | 55.9% | 1.34 | +26.3R | −9.02R | 5.18h |
| 上一版（key 0.8 / cap 5%） | 3.78 | 55.5% | 1.37 | +40.6R | −8.74R | 4.73h |
| **B 档（key 0.7 / 偏离 1.0×ATR20）** | **4.65** | **54.8%** | **1.36** | **+48.95R** | **−13.41R** | **3.98h** |
| B 档 · 池 50 | 5.85 | 53.8% | 1.28 | +49.2R | −12.66R | 4.05h |

**为什么停在 B 档**：单量比原方案 +74%，回撤只 +49%（回撤增速慢于单量），每笔仍 +0.1755R。再放一档（D 档 5.98 单/天）胜率就掉到 53.5%、盈亏比 1.26 —— 那是拿稳定性换单量。池子放到 50 更不划算：多 72 笔合计 −1.76R，每笔价值 −23%。

## 这套策略的弱点（诚实说明）

### 1. 没有闸能在 12 分钟内分辨真假突破

11-09 当天 4 笔大亏 −627 U（占当日 83%）全部在 **0.2 / 1.5 / 1.2 / 0.3 小时**内硬止损。
原快速失败闸要 4 小时才生效，根本来不及 —— **B 档已把它整条删除**，现在这条弱点没有任何闸能挡，属于已知风险。

当天 13 笔的 `dev` 全部 > 0.5%（最低 0.78%）→ 偏离闸一笔没挡住。现在偏离门槛改成自适应 1.0×ATR(20)（通常 0.4%~0.8%），比固定 0.5% 更贴当根波动，但对「瞬间插针式突破」依然无效。

**这是策略结构的固有弱点，不是参数能解决的。**

### 2. 利润高度依赖少数大赢单

任何「更早出场」的尝试都会砍到右尾。回测里试过六条路，全部让净 R 或回撤恶化。

### 3. 池子容量有限会漏掉机会

40 个位置按成交额排。热门币多了，质量不错但成交额低的币会被挤出去
（比如 SEI 成交额 10M，EFF 0.34 达标但排不进去）。

### 4. 实盘代码零真实验证

`backend/binance.py` 的实盘路径从未真实下过单。
市价单没有滑点保护，OKX 拒单会被当成成功（`data[0]["sCode"]` 从未检查），
`place_market_order` 没有 `newClientOrderId`（POST 绝不重试）。

**接实盘前必须先在测试网跑通验收 5 条**（见实盘检查清单）。

### 5. 交易所侧没有止损单

所有止损都在本地判断。**服务挂了 = 裸仓。**
这是已知问题，接实盘前必须解决。
