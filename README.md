从全市场 500+ 个合约里自动筛出可交易的，用趋势跟踪策略决定何时进出，

## 系统怎么运转（先看这个）

### 一句话版

> **每天筛 200 个 → 实时盯 40 个 → 每 15 分钟判一次能不能开 → 开了之后每 0.5 秒盯着要不要平。**

### 三层节奏（这是理解全系统的钥匙）

| 层 | 多久跑一次 | 干什么 | 代码 |
|---|---|---|---|
| **候选池** | 每天 03:00 | 从 500+ 个合约里选 200 个有波动潜力的 | `backend/pool.py` |
| **监控池** | **60 秒** | 给 40 个币算「有没有资格被交易」 | `backend/quality.py` |
| **策略扫描** | **15 分钟** | 判「现在能不能开仓」，能就下单 | `backend/strategies.py` |
| **持仓管理** | **0.5 秒** | 盯「要不要平仓」 | `backend/engine.py` |

**为什么进场慢（15 分钟）、出场快（0.5 秒）？**

因为这个策略的所有进场条件（CE 转向、HA 形态、BBW 分位、偏离均线）**都依赖 15 分钟 K 线的收盘价**。
K 线没走完时指标会来回闪，用未收盘的 K 线判信号等于自欺欺人。
把周期改成 5 分钟回测 2,504 笔 **−359R**（灾难），所以维持 15 分钟。

而仓位一旦开了，风险是**实时**的 —— 价格随时可能插针，所以出场检查跑在 0.5 秒。

```
    ╚═══════════════════════════════════════════════════════╝
```

### 关键设计原则

| 原则 | 为什么 |
|---|---|
| **进场判据必须用收盘价** | 未收盘 K 线的指标会闪，造成假信号 |
| **出场不依赖监控池** | 仓位一旦开了就是独立责任，掉出池也照常保护（出场遍历 `positions` 表） |
| **多空完全对称** | 代码是镜像的（已用镜像测试证明差 2.8R / 1.1R），空头赚得少只能是行情原因，不能是策略原因 |
| **单币独立风险** | 每笔按 R 计算，1R = 本金的 1.5%，不因仓位多少改变 |
| **不做马丁、不加仓、不摊平** | 一个仓位从开到平，只有「平一半」这一个中间动作 |

## 进场逻辑：一个币怎么被选出来并买入

### 第 1 关 · 候选池（每天一次）

```python
# strategies.yaml → pools.candidate
size: 200              # 取前 200 个
min_amp_pct: 10.0      # 30 天振幅 ≥ 10%
max_amp_pct: 300.0     # 且 ≤ 300%（排除刚上线的妖币）
vol_days: 30
```

**目的**：把 500+ 个合约缩到 200 个「有波动、有流动性」的池子。

### 第 2 关 · 监控池（每 60 秒）

四道资格闸，全过才进池：

| 闸 | 条件 | 参数 | 代码 |
|---|---|---|---|
| ① 止损距离 | 前 20 根阶段低/高点距离 ≥ **1.0%** | `stop_min_pct: 1.0` | `quality.py` |
| ② 趋势效率 EFF | ≥ **0.30**（96 根 15m = 24 小时窗口） | `eff_min: 0.3` | `quality.py::_eff` |
| ③ 成交额 | 24h ≥ **500 万 U** | `min_quote_vol: 5000000` | `quality.py` |
| ④ 插针 | 96 小时内最大插针 ≤ **8.0%** | `max_spike: 8.0` | `quality.py` |

**EFF（趋势效率）是什么，为什么不用涨跌幅：**

```
amp = (窗口内最高价 - 窗口内最低价) / 窗口内最低价
eff = |末收盘 / 首收盘 - 1| / amp
```

`eff = 1.0` 表示价格从最低点一路涨到最高点（完美单边）；
`eff = 0.1` 表示区间很大但价格来回震荡（宽幅震荡）。

**判据**（禁止用 24h 涨跌幅，那个数字区分不出「单边」和「震荡」）：

```
eff >= 0.55  单边趋势
eff <= 0.30  宽幅震荡 → 不进池
中间         半趋势
```

**池子是有限的（40 个位置），按 24h 成交额排。**
热门币多了，小币就被挤出去（这叫「池满未入选」，不是质量不行）。

**进池有保护**：进池后 900 秒内不会被踢（`min_dwell_sec`），防止指标抖动导致反复进出。
清退比进池宽松（`eff_exit: 0.25` vs `eff_min: 0.30`），也是防抖。

### 第 3 关 · 策略信号（每 15 分钟）

**只在监控池内的币上跑**，五道闸：

| 闸 | 条件 | 参数 |
|---|---|---|
| ① CE 方向翻转 | Chandelier Exit 方向由 −1 变 +1（做多）或反之 | `ce_len: 1` / `ce_mult: 2.0` |
| ② ATR 门槛 | **已关闭**（`min_atr_pct: 0`，池子已管） | — |
| ③ HA 关键 K 线 | Heikin-Ashi 出现同向关键形态 | `use_ha: true` |
| ④ BBW 分位 | 布林带宽度分位 > **70%**（波动正在放大） | `bbw_pct_min: 70.0` |
| ⑤ 偏离均线 | `\|当前价 − ZLSMA50\| / ZLSMA50 × 100` > **0.5%** | `min_dev_pct: 0.5` |

**止损价怎么定**：`swing_lookback: 20` → 做多取前 20 根最低点，做空取前 20 根最高点。

**⑤ 偏离闸是 11-09 新加的**，回测账：

```
744 笔 +78.1R  →  658 笔 +94.9R（少 86 笔，多赚 16.8R，回撤 −24.4 → −18.7）
```

被挡掉的那 104 笔（dev ≤ 0.5%）：−14.8R，胜率 34.6%，止损率 51.9%。
**贴着均线开的仓，本质是在赌突破，而突破大概率是假的。**

### 第 4 关 · 风控闸门（九道，见下一节）

### 第 5 关 · 下单

```
数量 = (本金 × 1.5%) / |开仓价 − 止损价|
```

市价单，逐仓 isolated，杠杆 6x（逐仓由代码自动设置，只对要开的币设）。

## 出场逻辑：一个仓位怎么被平掉

**跑在 `position_loop`，每 0.5 秒一轮，遍历 `positions` 表里所有开着的仓位。**

> **注意**：出场检查**完全不看监控池**。仓位就算掉出池了，六道出场一条不少。
> 池子只管「能不能开新仓」，管不到已开的仓。

### 六道出场（按检查顺序）

| # | 规则 | 触发条件 | 平多少 | 说明 |
|---|---|---|---|---|
| **0** | **硬止损** | 实时价触及止损价 | 全平 | 最优先，0.5 秒内响应 |
| **★1** | **快速失败** | 持仓 ≥ **4 小时** 且 峰值 R < **0.5** | 全平 | 11-09 新加 |
| **1** | **2R 平半** | 浮盈 ≥ **2R** | 平 50% | 只平一次（`half_closed` 标记） |
| **2** | **3R 全平** | 已平半，剩余仓位再赚 1R | 全平 | 合计 3R |
| **3** | **镜像出场** | CE 翻转 **且** HA 反向关键 K 线 **且** 破 ZLSMA50 | 全平 | 三条件同时成立 |
| **4** | **时间止损** | 持仓 ≥ **16 小时** | 全平 | 已平半的豁免 |

### 为什么是这个顺序

**硬止损必须最先** —— 它是唯一用实时价判断的，其它都用 K 线。
止损慢了就是灾难。

**快速失败放在 2R 平半之前** —— 逻辑上它判的是「这笔从一开始就错了」，
如果它成立，就不该走到「赚够了平一半」的流程。

**镜像出场需要三个条件同时成立**，任何一个单独都不可靠：

- 只有 CE 翻转 → 假信号太多
- 只有 HA 变色 → 是死闸（回测里去掉它结果完全一致，说明它从不单独触发）
- 只有破均线 → 太晚

三个一起：**趋势方向变了（CE）+ 形态确认了（HA）+ 价格跌破了均线（ZLSMA）**。

### ★ 快速失败闸（11-09 新加）

**逻辑**：开了 4 小时还没赚到 0.5R，说明这个信号从一开始就是错的。

回测账：

```
744 笔 +78.1R  →  782 笔 +109.0R（多 38 笔，多赚 30.9R，回撤 −24.4 → −21.4）
```

**为什么是 4 小时 / 0.5R 而不是别的**：全档跑过，
2h 太早（会砍掉正在启动的仓位），6h 太晚（亏损已经扩大），4h / 0.5R 是最优组合。

### 出场侧已经试过、全部否掉的方向

| 方向 | 结果 | 结论 |
|---|---|---|
| 离均线更早平（≤0.35%） | +85.8R 但回撤 −25.3 | 回撤恶化，不过 |
| 去掉 HA 闸 | +76.1R（与现状完全一致） | HA 是死闸，但去掉也没好处 |
| 去掉 CE 闸 | +44.0R / 回撤 −37.8 | CE 不可替代 |
| 只留破均线 | +40.0R / 回撤 −43.1 | 灾难 |
| 峰值回吐（0.3R / 1.0R） | +15.4R / +83.3R | 砍掉右尾，不如现状 |
| 加「出场距离 ≥0.5%」 | +79.4R 但回撤 −26.1 | 实质废掉镜像出场（175 笔 → 122 笔） |

**根本原因**：S15 的利润 = **少数大赢单养多数小亏单**。
任何「更早 / 更频繁」的出场，砍到的都是那些大赢单。

详见 [`docs/S15_参数优化证伪记录.md`](docs/S15_参数优化证伪记录.md)。

## 风控：下多少、能开几个

### 九道进场闸（`risk.allow_entry`）

| # | 闸 | 参数 |
|---|---|---|
| 1 | 日熔断（当日亏损 ≥ 10%） | `daily_loss_halt_pct: 10.0` |
| 2 | 日目标（当日盈利达标后停开新仓） | `daily_target.target_usd: 500` |
| 3 | 事件静默（重大事件前后 30 分钟） | `event_quiet_minutes: 30` |
| 4 | 并发币种数 | `max_concurrent_coins: 8` |
| 5 | 同向持仓数 | `max_same_side: 6` |
| 6 | 总杠杆 | `max_gross_leverage: 6` |
| 7 | 单币名义上限 | `max_position_pct_per_coin: 32.0%` |
| 8 | 单笔风险比例 | `risk_per_trade_pct: 1.5%` |
| 9 | 同币冷却 | — |

### 方案 Z（当前生效）

```
risk_per_trade_pct      : 1.5%      → 1R ≈ 150 U（1 万本金）
max_concurrent_coins    : 8         → 最多持 8 个币
max_same_side           : 6         → 同向最多 6 个
max_gross_leverage      : 6x        → 总敞口上限 6 倍
max_position_pct_per_coin: 32%      → 单币名义上限
daily_loss_halt_pct     : 10%       → 日亏 10% 全停
daily_target            : 500 U     → 日赚 500 停开新仓（可手动重置）
```

**60 天回测**：+5,283 U / 回撤 2,947 U / 最低净值 7,058 U。

### 三个容易踩的坑（已写进文档）

1. **不改单币上限，风险比例白改** —— 单币名义被 32% 截断时，1.5% 的实际含义就变了
2. **回测必须补并发模拟** —— 单币独立跑出来的收益是假的（并发 3 只吃 18.75R，并发 6 吃 35.20R）
3. **接实盘第一件事是把 cross 改 isolated** —— 现在 OKX / Bitget 写死全仓

## 快速开始

### 环境要求

- Python 3.11+
- Node.js 18+（只构建前端时需要）
- Windows / Linux / macOS

### 安装

```bash
git clone https://github.com/ha56412003-lab/quant-bot.git
cd quant-bot

# 后端
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt

# 前端
cd frontend-v2
npm install
npm run build
cd ..
```

### 配置

```bash
# 复制环境变量模板，填入你自己的密钥（不要提交到 git）
cp .env.example .env
```

**必需的环境变量：**

| 变量 | 说明 |
|---|---|
| `CLAWBY_API_KEY` | 行情数据源（[Clawby](https://openclawby.com)） |
| `BINANCE_API_KEY` | 可选，接实盘时才需要 |
| `BINANCE_SECRET_KEY` | 可选 |
| `QB_SAMPLE_START` | 可选，测试取样起点，默认 `2026-11-09 12:00` |

**API 权限（币安）**：只勾「允许读取」+「允许合约」，**绝不勾提币**。
必须设置 **IP 白名单** —— 币安规则：无限制 + 有非读取权限 = **密钥会被删除**。

### 启动

```bash
# Windows（无窗口后台运行）
run_hidden.vbs

# 或前台运行看日志
run_server.bat
```

打开 <http://127.0.0.1:8899>

### 测试

```bash
python tests/run_all.py            # 跑全部
python tests/run_all.py gates      # 只跑名字含 gates 的
```

测试文件是**脚本式**的（每个自带 `main()` 和退出码），不依赖 pytest。

> ⚠️ **测试约定**：任何测试脚本**不得对生产库 `quantbot.db` 有写操作**。
> 有副作用的函数一律打桩，有 `DELETE` 的测试一律换临时库。
> 这条是踩过两次雷换来的（曾把生产的 `system_alerts` 历史告警清空过一次）。

## 这套策略的弱点（诚实说明）

### 1. 没有闸能在 12 分钟内分辨真假突破

11-09 当天 4 笔大亏 −627 U（占当日 83%）全部在 **0.2 / 1.5 / 1.2 / 0.3 小时**内硬止损。
快速失败闸要 4 小时才生效 —— 根本来不及。

当天 13 笔的 `dev` 全部 > 0.5%（最低 0.78%）→ 偏离闸一笔没挡住。

**这是策略结构的固有弱点，不是参数能解决的。**

### 2. 利润高度依赖少数大赢单

任何「更早出场」的尝试都会砍到右尾。回测里试过六条路，全部让净 R 或回撤恶化。

### 3. 池子容量有限会漏掉机会

40 个位置按成交额排。热门币多了，质量不错但成交额低的币会被挤出去
（比如 SEI 成交额 10M，EFF 0.34 达标但排不进去）。

### 4. 实盘代码零真实验证

`backend/binance.py` 的实盘路径从未真实下过单。
市价单没有滑点保护，OKX 拒单会被当成成功（`data[0]["sCode"]` 从未检查），
`place_market_order` 没有 `newClientOrderId`（POST 绝不重试）。

**接实盘前必须先在测试网跑通验收 5 条**（见实盘检查清单）。

### 5. 交易所侧没有止损单

所有止损都在本地判断。**服务挂了 = 裸仓。**
这是已知问题，接实盘前必须解决。
